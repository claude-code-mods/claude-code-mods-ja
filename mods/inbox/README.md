# Inbox

> 日本語版は claude-code-mods-ja プロジェクトによる翻訳です。原作者とライセンスは文末に記載されています。原版の README は [README.en.md](README.en.md) をご覧ください。

ADHD 持ちです。チャットスレッド形式でエージェントと作業するのは、認知的にかなり負担が大きいものです。セッションが長引くほど、頭の中で把握しておかなければならないことが積み重なっていきます。質問、バグ、アイデア、タスクがすべて積み重なり混ざり合って、すべてを整理しておくのが難しくなります。

Inbox は、判断が必要なものをすべてエージェントが提示するための、整理された安定した場所を与えることで、この問題をすぐに解決します。さらに Inbox は、各項目について推奨アクションを含む先回りしたクイックアクションを、エージェントが必ず提示するようにします。

それだけではありません。Inbox は、目の前のタスクだけに対応するために見落とされがちな、潜在的な問題や機会をエージェントが拾い上げるための場所も提供します。

Inbox はターミナルとデスクトップアプリの Claude Code、ChatGPT デスクトップアプリの Codex、そしてターミナルの omp で使えます。Herdr アプリでは、ターミナルの脇のペインで開くこともできます。各バリエーションはプラットフォームごとに作り込まれていますが、基本的な動作はどれも同じです。

## インストール

私のような人なら、この GitHub リポジトリのリンクをそのままエージェントに貼り付けて、インストールを頼めばいいでしょう。

古風なやり方が好みなら、以下を進めてください。

### Claude Code

ターミナルの Claude Code セッションで、次を入力します：

```
/plugin install inbox --marketplace petekp/inbox
```

marketplace を追加するか尋ねられたら `y` と答え、スコープを選びます。そのセッションですぐに動作し始めます。ユーザースコープでインストールすると、このマシン上の Claude デスクトップアプリの Code セッションでも使えます。

代わりに Claude デスクトップアプリからインストールするには、Code セッションを開きます：

1. 入力欄の横の **+**、次に **Plugins**、**Manage plugins** をクリックします。
2. Plugins ページで右上の **Add**、次に **Add marketplace**、**Add from a repository** をクリックします。
3. `petekp/inbox` と入力し、一覧から **inbox / petekp** を選んで **Sync** をクリックします。
4. Inbox で **Add to this computer** をクリックします。
5. セッションに戻り、`/inbox` と入力してペインを開きます。

これはユーザーアカウントに対してインストールされるため、ターミナルでも動作します。デスクトップアプリでは `/plugin` は動作せず、inbox はアプリのクラウドセッションには届きません。

組織が Claude Code を管理している場合、自分でインストールした inbox も 2 点を除いて動作します。`/clear` や再開後は、最初のメッセージを送った時点でその会話のリストを読み込みます。permission のプロンプトは、表示されてから約 1.5 秒後に inbox に届きます。すべてを取りこぼさないには、管理者に組織の管理設定に inbox を登録してもらってください。

更新するには次を実行し、すでに開いているセッションで `/reload-plugins` を実行します：

```sh
claude plugin marketplace update inbox
claude plugin update inbox
```

- Claude の返答ごとに 2 回 Sonnet を呼び出します。1 回は行用、もう 1 回は Status タブ用です。[コスト](#コスト)を参照してください。
- Claude Code 2.1.300 で開発・テストされました。

### Codex

```sh
codex plugin marketplace add petekp/inbox
codex plugin add inbox@inbox
```

シェルが `command not found: codex` と言う場合は、両方のコマンドの `codex` の代わりに ChatGPT アプリ内のコピーを使ってください：

```sh
/Applications/ChatGPT.app/Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex
```

次に ChatGPT デスクトップアプリで、プラグインのフックを信頼します。入力欄の承認設定の横にあるフックアイコンをクリックし、Allow all を選びます。アイコンがない場合は、Settings、Hooks、Inbox、Trust all の順に開きます。Codex はプラグインのフックを信頼した後にだけ実行します。Codex 0.164.0 以降では、更新するとフックが停止するため、更新のたびに再度信頼してください。inbox を開くには、サイドパネルを開き、New の横の ⋯ メニューから Inbox を選びます。これは 2026-11-14 に Codex 0.169 の ChatGPT アプリで確認しました。

[codex/README.md](codex/README.md) に更新方法とアプリ内の `codex` コマンドの実行方法が記載されています。

### omp

```sh
omp plugin marketplace add petekp/inbox
omp plugin install inbox@inbox-omp
```

inbox は次の omp セッションから動作します。`omp plugin list` には `inbox@inbox-omp` と表示されます。omp が Claude Code 用の `.claude-plugin/` フォルダより先に探す `.omp-plugin/marketplace.json` を読み込みます。

更新するには次を実行し、omp を再起動します：

```sh
omp plugin marketplace update inbox-omp
omp plugin upgrade inbox@inbox-omp
```

返答ごとに、inbox は 2 回モデルを呼び出します。1 回は行の更新、もう 1 回は Status タブの書き込み用です。omp が実行できる最初のものを使います：

1. `@inbox` ロールが指定するモデル。
2. プロバイダーの中で最新の Sonnet（`anthropic` を優先）。
3. `@smol` ロール。

`@inbox` を設定するには、omp の `config.yml` の `modelRoles` に追加してから omp を再起動します：

```yaml
modelRoles:
  inbox: anthropic/claude-sonnet-5-5
```

テストされているのは Sonnet のみです。他のモデルでも動くかもしれませんが、どの程度かは誰も確認していません。

呼び出しごとの請求は、そのモデルのレートでプロバイダーに行われます。

`@inbox` が未設定か、omp が使えないモデル（未知のモデルやサインインしていないモデルなど）を指定している場合、inbox は次の選択肢を使います。パネルのフッターに使用中のモデルが表示されます。omp が使えるにもかかわらず呼び出しに失敗したモデルはフォールバックしません。その更新は失敗し、次の返答で再試行されます。使えるモデルがない場合、フッターには「no inbox model: set @inbox」と表示され、inbox は更新できません。

### すべての環境

PRs タブには、サインイン済みの GitHub CLI `gh` が必要です。

## 使い方

Claude Code または omp で `/inbox` と入力するか、ChatGPT アプリで Inbox タブを開きます。inbox には Status、Asks、Finds、PRs の 4 つのタブがあります。

inbox は最初空です。エージェントにタスクを与えると、その返答の後に最初の行が表示されます。あなたに尋ねた質問（回答がボタンになります）と、作業の Status です。Claude Code では、inbox に何か入ると入力欄の上の行に表示されます。

すべての部分をサンプル項目付きで見るには、Claude Code または omp で `/inbox demo` を実行します。ボタンを押しても変わるのはサンプルだけです。Claude Code では、Hide demo を押すか同じコマンドをもう一度実行すると元に戻ります。`/inbox demo recording` は動画用に、サンプルを示す通知を省略します。omp では、パネルを閉じるまでサンプルが残ります。

### Status

久しぶりに戻ってきた人向けに、セッションの作業が今どこにあるかを示します。このページは、セッションが今何に集中しているかを名指しし、作業の各部分とその進捗を挙げます。1 日アイドルになっている部分は、どれだけ経ったかを表示します。部分の下には、サブエージェントやその他の進行中の作業が表示されます。あなたの質問やタスクを待っている部分はその旨を表示し、View で開けます。最後に見た場所に線が引かれ、それ以降に変わった内容が上に表示されます。終了した作業は、開ける件数にまとめられます。

「ストアで 2.5」のようなゴールと完成ラインを設定できます。するとページはゴールのマイルストーンごとに作業をまとめ、inbox がゴールとマイルストーンを最新に保ちます。ゴールはいつでも編集・削除できます。自分で入力したゴールは達成されるまで残ります。inbox が推測したゴールは、作業の進行に合わせて進みます。

このページは作業のガイドであり、ログではありません。各返答後の 2 回目のモデル呼び出しで書き込まれます。その呼び出しが失敗すると、その旨が表示されます。

### Asks

エージェントがあなたに尋ねた質問と、あなたにしかできないタスクです。

エージェントは質問をここに置くために特別なことをする必要はありません。返答のたびに、モデルがエージェントの書いたものを読み、考えられる回答とともに各質問を記録します。エージェントが推奨する回答が最初に来ます。回答を押すと、数秒後にあなたのメッセージとしてエージェントに届きます。誤って押した場合は Undo で取り消せます。自分で返信を入力したり、Explain を押してエージェントにもっと説明させてから決めることもできます。

2 つのレイアウトや機能の実装方法など、質問がデザインの選択である場合、Compare はエージェントに各回答をあなたのコードに対して試させ、並べて比較するページを作ります。ページは質問から開けます。ページはエージェントの選択を先頭に置き、エージェントの返答に選択内容、理由、ページのパスが書かれます。エージェントがバックグラウンドでサブエージェントを実行できる場合、比較はそこで行われるため、作業を続けられます。エージェントが報告するまで質問には「Comparing…」と表示されます。30 分経っても報告がない場合は「No comparison came back」と表示され、Compare をもう一度押せます。

タスクとは、サインインや API キーの追加のようなものです。手順用のボタンが付いており、コマンドのコピーやファイルを開くことができます。Claude Code では、`!` でコマンドを実行して成功するとタスクが閉じます。Dismiss は、エージェントにメッセージを送らずに、やらないタスクを破棄します。

### Finds

エージェントが現在のタスクの範囲外で気づいたバグ、リスク、アイデアです。エージェントはこれらを記録してタスクを続け、どれに対応するかはあなたが後で決めます。問題に対して Fix、アイデアに対して Do it を押すと、エージェントに渡されます。File issue は、Linear や GitHub などの issue トラッカーに登録するか、すでに同じ内容を扱っている issue をリンクします。Reply はあなた自身の言葉でコメントを送ります。Explain は、なぜ重要なのか、修正に何が伴うのかをエージェントに説明させます（実際には行動しません）。Discuss は議論し、Dismiss は破棄します。

### PRs

このセッションと現在のブランチのプルリクエストです。それぞれ Blocked、Ready、Waiting のいずれかで表示され、ブロックしているもの（あなたを待っているレビューコメント、失敗しているチェック、マージコンフリクト）を挙げます。ボタンで作業をエージェントに渡せます。レビューコメントを 1 件またはすべて対応する、返信の下書きを作る、失敗したチェックを直す、コンフリクトを解消する、マージする、などです。Fix と Resolve conflicts は、GitHub がまだ問題を表示している間だけ出ます。マージまたはクローズされた PR はタブから自動で消え、Undo で残せます。タブ上部の Clear merged and closed は、残っているものを、現在のブランチ自身の PR 以外すべて消します。

エージェントが PR に順番を付けることもできます。たとえば、どれを先にマージするかです。その場合、タブには順番の目的と理由を添えて、番号付きで先に表示されます。順位付けされた PR が変わると、タブにその旨が表示され、Rank がもう一度提案されます。

### 自動で最新を保つ

自分のメッセージで質問に答えたり、タスクが完了したり、エージェントが finding を修正すると、inbox は項目を閉じます。閉じた項目は開いている項目の下にたたまれ、それぞれどう終わったかが示されます。破棄した項目は、セッションの残りの間 Reopen が残ります。

エージェントも inbox を読みます。各プロンプトの隣に、まだ開いているものとあなたの回答を、会話が compact された後でも見られます。

ボタンを押すと、その結果がすぐに表示されます。Discuss はエージェントが返答するまで「Discussing…」、その後「✓ Discussed」と表示されます。

### アプリごとの違い

Help にキーと各記号の意味が載っています。

- **ターミナル：** 各アクションに、それを実行する文字が表示されます。数字キーでタブを切り替え、`j` と `k` で上下に移動します。Status では、ボタンのある行間を移動し、ボタンの横の文字を押すとそのボタンが押されます。ctrl+x tab でフォーカスがプロンプトからその上の行へ、次にパネルへ、そして再びプロンプトへ移ります。
- **Claude デスクトップアプリ：** クリックします。`/inbox` と入力するとペインが開きます。ペイン内のクリックは Claude Code エンジン 2.1.309 以降で確認済みです。2.1.295 では、押した後にクリックしてもペインにフォーカスが戻るだけでした。
- **ChatGPT アプリ：** クリックするか、ターミナルと同じキーを押します。タブには文字は表示されません。
- **Herdr アプリ：** [Herdr アプリのペイン](#herdr-アプリのペイン)を参照してください。
- **omp：** `/inbox` で会話の上にパネルが開き、esc で閉じます。各アクションに実行文字が表示され、Reply は `t` です。矢印キーで行間や行内のボタン間を移動し、enter でフォーカスのあるボタンを押します。Tab または数字キーでタブを切り替えます。Status では `j` と `k` でボタンのある行間を移動し、上下矢印でページをスクロールします。

Claude Code では、入力欄の上の行に、あなたを必要とするものと待っている findings の件数が表示され、パネルを開くボタンが付きます。エラーで停止した場合は 2 行目に理由が表示され、API エラーの後には Resume ボタンが出ます。ChatGPT アプリにはそのような行はありません。omp には同じ件数を表示する行があります。`/inbox` でパネルを開くと表示され、停止行はありません。

### Herdr アプリのペイン

Herdr アプリのターミナルでは、inbox をターミナルの脇のペインで開けます。

1. Herdr アプリのターミナルで Claude Code または omp を起動し、`/inbox` と入力します。初回は inbox がターミナル内で開き、「Install the inbox's Herdr mod?」と尋ねられます。Install を押してください。ChatGPT アプリでも Inbox タブで同じ質問をされます。
2. もう一度 `/inbox` と入力します。inbox がターミナルの右側のペインで開きます。Claude Code の Open inbox ボタンでも同じ結果になります。別のセッションやアプリで Install を押したのに inbox がターミナルで開く場合は、Claude Code を再起動してください。
3. ペインには、そのタブで最後にフォーカスしたターミナルの inbox が表示されます。Asks、Finds、PRs があり、すべてのボタンを押せます。← と → でタブを切り替え、`j` と `k` で行間を移動し、esc でキーをターミナルに戻します。残りは Help に載っています。

Don't install を押すと回答が保存されます。Claude Code または omp で `/inbox herdr` を実行すると、もう一度尋ねられます。

Codex CLI には `/inbox` がありません。代わりに `herdr-app do pane.split '{"direction":"right","pane":"<pane id>","mod":"inbox"}'` でペインを開きます。ペイン id は `herdr-app ls` から取得します。

Herdr ペイン内では、Claude Code、omp、Codex CLI も pane tokens として Herdr のサイドバーに報告します：

| Token | 内容 |
|---|---|
| `inbox` | あなたを待っているものを 1 行で示します |
| `inbox-needs-you`, `inbox-findings`, `inbox-prs` | タブの件数だけ（`2` など）。`inbox-needs-you` は Asks タブ、`inbox-findings` は Finds タブのものです。タブに待ち項目がない場合は空になります。 |
| `inbox-stop` | エージェントが停止した理由。停止が解除されるまで件数トークンは空のままで、サイドバーにその分の余白が確保されます。 |
| `inbox-focus` | Status 由来の、セッションが集中している内容。このセッションを Herdr の delegate として開始したセッションは、delegate の行として表示されます。サイドバーの行では不要です。 |

タブの色で件数を見分けるには、Herdr の設定の `[ui.sidebar.agents]` の `rows` に次の行を追加します：

```toml
[
  { token = "$inbox-stop", fg = "#ffa3b0" },
  { token = "$inbox-needs-you", fg = "#ffae42" },
  { token = "$inbox-findings", fg = "#cab0ff" },
  { token = "$inbox-prs", fg = "#8cc8c0" },
],
```

Herdr は値を持つトークンの間に ` · ` を入れ、どれも値がない場合は行を出力しません。

## コスト

Claude Code では、inbox は 2 つのものを追加します：

| inbox が追加するもの | トークン | API 価格でのコスト |
|---|---|---|
| Claude の返答ごとの、inbox 更新用 Sonnet 呼び出し | 入力 3〜4k（うち約 2k がキャッシュ）、出力 100〜250。 | 返答あたり約 0.5 セント、5 分アイドル後は 1 セント |
| Status タブを書くための 2 回目の Sonnet 呼び出し | 短いやり取りでは入力約 1.2k、出力 14〜44（3 回の eval 実行で入力 1,175〜1,214）。会話の追いつきにはより多く読み、1 回の実行で入力 1,358、出力 100 でした。 | 約 3k を読む 1 回目より少ない |
| Claude のすべてのリクエストに送られる指示とツール | 約 1,350（キャッシュ済み） | リクエストあたり 0.1 セント未満 |

Claude のプランを使っている場合、これらは利用制限にカウントされます。

Codex では、返答ごとの更新はデスクトップアプリ内の `codex` バイナリを、あなたの Codex サインインで実行します。返答ごとに 2 回呼び出します。それぞれ、すべての `codex exec` 呼び出しに含まれる基本指示の入力トークン約 12,000 に加え、独自のプロンプトを運びます。以前の 1 回の呼び出しは約 16,000 でした。プランの利用量にカウントされます。

## 実行、送信、変更の内容

ここでは Claude Code の mod を説明します。[codex/README.md](codex/README.md) に Codex プラグインの説明があります。omp 拡張も同じ `gh` クエリを実行します。更新リクエストは、使用するモデルのプロバイダーへの omp 自身の接続を通り、Claude Code のリクエストと同じものを含みます。

**マシンから出ていくもの。** 次の 3 つだけで、それ以外はありません：

- Claude の返答ごとに、inbox は Claude Code 自身のモデル接続を通して 2 件の Sonnet リクエストを Anthropic に送ります。どちらも直近のプロンプト、Claude の返答、inbox の開いている項目、そして Claude が実行したツールごとの行を含みます。ツール行は `ran: npm test` や `edited src/app.ts` のようになります。リクエストのサイズは[コスト](#コスト)を参照してください。
- inbox がターンを取りこぼした可能性がある場合、同じモデルに同じ 2 回の呼び出しで会話全体から更新させます。そのために会話を fork するか、再開後にトランスクリプトを読みます。
- PRs タブを埋めるために、読み取り専用の `gh` クエリ（`gh pr view` と、レビュースレッド用の `gh api graphql`）を実行します。あなた自身の `gh` サインインで GitHub に届きます。inbox が GitHub トークンを読むことはありません。

**起動するプログラム。**

| プログラム | タイミング |
|---|---|
| `gh` | PRs タブを埋めるとき |
| `open` | リンク、ファイル、フォルダを開くボタンを押したとき |
| `test -x` | ファイルを開く前。実行可能ファイルは実行せず Finder に表示します。 |
| `herdr pane report-metadata` | Herdr ペイン内のみ。あなたを待っているものと各タブの件数を Herdr のサイドバーに表示するため |

**あなたの代わりに送るメッセージ。** 回答やアクションのボタンを押すと、inbox はあなたの名前で Claude にメッセージを送ります。その内容は選んだ回答か、項目についての依頼（finding を直すよう頼むなど）です。停止したターンで Resume を押すと `Continue` を送ります。送るメッセージはすべてボタンを押すことから始まります。Claude が待っているタスクを Done にすると、inbox は数秒後、あるいは Claude の実行中のターンが終わった時点でその旨を伝えます。

**Claude のコンテキストに追加するもの。**

- すべてのリクエストに含まれる、約 1,350 トークンの指示。
- Claude の番号付き質問に答えたとき、または inbox が前回 Claude が見てから変わったときに、プロンプトの隣に置かれるメモ。
- 会話が compact された後の開いている項目。Claude がそれらを保持できるようにするためです。

**フックが見るもの。**

- ツール呼び出し。上記のツール行を書くため、Claude の質問ダイアログが開いている間に質問を表示するため、このセッションで `gh pr create` で開いた PR を見つけるために、各呼び出しを読みます。自身の 2 つのツールへの呼び出し以外は、すべてそのまま渡します。`record` は質問、タスク、finding を保存し、`close` は項目を閉じます。inbox 自身がこれらに回答するため、permission のプロンプトなしで実行されます。
- permission のプロンプト。Claude Code がツール呼び出しの承認を求めている間、inbox はその行を表示し、リクエストはそのまま渡します。承認も拒否も一切しません。
- ツールの説明。自身の 2 つのツールを、ツール検索の背後ではなく、最初から Claude に一覧で提示します。他のツールの説明は変更しません。
- `!` で実行したシェルコマンドとその出力。stderr に何も出さずに実行されたコマンドは、その実行を求めていたタスクを閉じます。
- セッションの開始。`/clear`、再開、fork の後、その会話の項目を読み込みます。イベントはそのまま渡します。
- テーマ設定。色を合わせるために使います。

**保存するもの。** 各セッションの項目と追跡中の PR を、このマシン上の Claude Code のプラグインストレージに保存します。直近の 40 セッションを保持し、古いものは削除します。項目には会話の一部が要約されることがあるため、関係者の名前が入る場合があります。プラグインの作者には何も送られません。

さらに `/inbox` コマンドを追加します。
