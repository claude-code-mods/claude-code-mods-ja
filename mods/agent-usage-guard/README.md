消費の後ではなく前に動きます：エージェントの開始、プロンプトの送信、ツール呼び出しの実行の前に確認します。エージェントの上限は、あなたのマシン上のすべての Claude Code セッションに適用されます。並立数と重いコンテキストは、上限に近いときだけでなく、どのような使用率でも制限されます。あなたがキーボードにいるときは、Claude Code 自身の質問ダイアログで尋ねます。誰も回答できないときは拒否し、その理由を Claude に伝えます。待機したり、作業をまとめたり、停止したりできるようにするためです。`/agent-guard report` で動作を確認できます。

- **プランを把握。** Claude Code が報告する 5 時間と週次の割合を読み、ウィンドウの終わりをあなたのために取っておきます。
- **一度の回答でしばらく有効。** 承認すると、その条件が解消されるかタイムアウトするまで解除されたままなので、同じ質問が呼び出しごとに繰り返されません。
- **ローカルでプライバシーへの影響が最小。** ネットワークもプロセスも使いません。保存するのは回数と粗い区分だけで、プロンプト本文、ツールの入力、モデルの出力は保存しません。
- **失敗時は通す。** フックの 1 つが失敗してもイベントはそのまま進みます。壊れたガードがセッションを壊すことはありません。唯一の例外は、判定できなかったエージェントで、Claude が再び開始できるよう拒否します。

## インストール

Claude Code v2.1.287 以降で、次のコマンドを実行してください：

```text
/plugin marketplace add rbartoli/agent-usage-guard
/plugin install agent-usage-guard@agent-usage-guard
/reload-plugins
```

次に `/agent-guard` を実行してガードが見ているものを確認し、`/agent-guard simulate concurrency` でエージェントが多すぎるときにどんな質問をするのか確認できます。どちらも実際に保留したり消費したりはしません。mod はデフォルトで有効です。無効にする設定は[概要](https://code.claude.com/docs/en/plugins/mods/overview#turn-mods-on-or-off)に記載されています。

## なぜ作ったのか

ある午後、Claude Code に最大の試行レベルで調査のプロンプトを与えました。**394 回のサブエージェント呼び出しが発生し、そのうち 341 件が同時に動き、10 分間で 8400 万のコンテキストトークンが API を通過しました。** セッション終了：*「Claude usage limit reached.」* ウィンドウがリセットされるまでロックアウトされました。

一度きりのことではありません。自分のログ 60 日分には **12 回のロックアウト** と、エージェントのバーストがあった 166 個の 10 分間ウィンドウがありました。この失敗は掛け合わさって起きます：*大きなコンテキスト × 速いツールループ × 並列エージェント × 盲目的なリトライ*。以下の各保護は、その要因を 1 つずつ取り除きます。

私だけではありません：[1 つのプロンプトから 339 のサブエージェント](https://www.reddit.com/r/ClaudeAI/comments/1u5d02w/)、[再帰的な生成で Max プランの週次枠の半分を消費](https://github.com/anthropics/claude-code/issues/68619)、そしてマルチエージェント実行は[チャットセッションの約 15 倍のトークン](https://www.anthropic.com/engineering/built-multi-agent-research-system)を使います。

## 何をするのか

| 領域 | ルール | デフォルト | 動作 |
|---|---|---|---|
| プランのウィンドウ | 使用率がこの値に達すると、新しいエージェントに承認が必要 | 80% | 尋ねる；承認はそのウィンドウがリセットされるまで有効 |
| | 使用率がこの値に達すると、新しいエージェントを拒否 | 95% | 拒否 |
| | 使用率がこの値に達すると、`ScheduleWakeup` と `CronCreate` を拒否し、ターンが勝手に上限へ向けて始まらないようにする | 95% | 拒否 |
| | 各セッションに 1 度だけ、ステップを終えて残りを伝えるよう指示 | 95% | 次のプロンプトに注意書きを追加 |
| | 5 時間ウィンドウがこの速さで上昇すると、新しいエージェントに承認が必要 | 10 分あたり 20 ポイント | 尋ねる |
| | 直近 10 分のペースで 1 時間以内にウィンドウが埋まる見込みなら、リセット前に新しいエージェントに承認が必要 | 2 分で少なくとも 2 ポイント | 尋ねる |
| エージェント | このマシンの全セッションを通じて同時に動いているエージェント数 | 4 | 尋ねる |
| | このマシンで 10 分あたりに開始／再開されるエージェント数 | 12 | 尋ねる |
| | このマシンで 10 分あたりにサブエージェントが処理するトークン数；承認は 1 時間有効 | 10M | 尋ねる |
| | サブエージェントは自分のエージェントを開始できない | 深さ 1 | 拒否 |
| コンテキスト | ターンを限定するよう Claude に一度だけ伝える | 300k トークン | プロンプトに注意書きを追加 |
| | これだけのコンテキストを再読み込みしようとするプロンプト | 500k トークン | 尋ねる：圧縮して送信、そのまま送信、キャンセル |
| | 会話やエージェントがこれだけのコンテキストを持っている間の 10 分あたりのツール呼び出し | 400k で 20 回 | 尋ねる：続ける、このターンの後に圧縮、停止 |
| | 重いセッションが長くアイドルでプロンプトキャッシュが切れた場合 | 150k トークン、1 時間アイドル | キャッシュの書き直し前に尋ねる |
| ループ | 同じツール呼び出しが繰り返し失敗し、間に別の呼び出しがない | 同一の失敗 3 回 | 同じ再試行を拒否 |
| | 10 分以内に拒否されたエージェント呼び出し | 5 | 10 分間エージェントの生成を一時停止 |

エージェントには、サブエージェント、エージェントチームのチームメイト、ワークフローエージェント、`SendMessage` で再開された完了済みサブエージェントが含まれます。Haiku エージェントは、Claude が Haiku を選んだ場合でもエージェント定義自体が選んだ場合でも、実行中と開始数の上限からは除外されます。ただしサブエージェントのトークン予算とプランウィンドウのルールには数えられます。各ツール呼び出しは、それを含むループのコンテキストで判定されるため、小さなサブエージェントがメイン会話の大きさを引き継ぐことはありません。

**尋ねるとき。** 質問は、Claude があなたに何かを尋ねるときに使う Claude Code 自身のダイアログに表示され、呼び出しは回答を待ちます。表示中に並列で開始されたエージェントは保留され、回答後に Claude が再び開始します。許可すると、その条件はしばらくの間許可されたままになります：プランウィンドウならリセットされるまで、重いコンテキストなら小さくなるまで（ツール呼び出しの場合は最大 1 時間）、エージェント数なら 10 分間です。拒否するか、質問を閉じるか、その他の理由で回答なしに閉じると、次の 10 分間はエージェントを開始しないよう Claude に伝えられ（`AGENT_GUARD_WINDOW_SECONDS`）、その間は再び尋ねられません。入力した言葉は Claude に届くので、「代わりに haiku エージェントを使って」と答えることもできます。

**誰も回答できないとき。** `claude -p`、Agent SDK、`dontAsk` モードでは、エージェントやツールのゲートは尋ねる代わりに拒否します。重いプロンプトは理由とともに保留され、マシン全体で 10 分に 1 件という上限に達した後の休眠中の重い再開も同様です。スケジュールや `/loop` の発火、Slack などチャンネルから中継されたメッセージ、Slack のピングなど、自らターンを始めるプロンプトも同じように保留されます。人が尋ねられるセッションでも同様で、上限を解除することはありません。Claude は各拒否をツールの結果として読み取ります。同じ条件の拒否は毎回異なる言い回しで行われ、段階的に強くなります：2 回目は何も変わっていないので別の方法を試すよう伝え、3 回目はターンを終えるよう伝えます。`/goal` のような Stop フックがターンを開き直し続ける場合、拒否はユーザーが判断する必要があると伝えます。

**表示されるもの。** このマシンでエージェントが動いている間、ガードが何かを保留している間、あるいは拒否した直後は、プロンプトの上に 1 行が表示されます：`Usage guard · 3 of 4 agents running · 5 of 12 started in the last 10 min · last refusal 14:22: concurrency`。上限に達したか何かが保留されると太字になり、何も言うことがなければ消えます。Claude Code の `[-]` で折りたためます。プランウィンドウとコンテキストはステータス行に残ります。

**触らないもの。** バックグラウンドタスクの通知や他のセッションのメッセージは、結果が失われるため保留しません。利用上限後のプロンプトもブロックしません。v2.1.234 以降、Claude Code は上限で待機し、リセット時に自動的に続行します（`autoContinueAtUsageLimit`）。ガードの役割は上限に達する前に止めることで、ジャーナルには防げなかったロックアウトも記録されます。上限近くでは注意書きを追加するだけです：95% 以降、各セッションの次のプロンプトは Claude に、進行中のステップを終え、大きなことは始めず、完了したことと残っていることを添えてターンを終えるよう伝えます。ロックアウトが起きても、どのセッションもきれいな停止点にあります。

**アイドル時の圧縮。** v2.1.299 以降、Claude Code は約 54 分間アイドルで 20 万トークン以上の会話を、1 時間のプロンプトキャッシュが切れる前に圧縮します（`idleCompaction`、デフォルト有効）。ガードは圧縮後のサイズを読むため、そのセッションについて尋ねません。v2.1.314 以降は、テレメトリを無効にした加入者の VS Code と Claude Desktop の Code タブでも、また 1 時間のプロンプトキャッシュが有効な Bedrock、Vertex、Foundry、LLM ゲートウェイでも動作します。休眠中の質問は、アイドル圧縮がカバーしないものを扱います：15 万〜20 万トークンの会話、`claude -p` と SDK のセッション、54 分時点でマシンがスリープしていた場合、アイドル圧縮や自動圧縮を無効にしている構成です。

**Claude Code 自身の再開警告。** v2.1.304 以降、Pro と Max プランでは、非アクティブな会話を再開したり、アイドル中にキャッシュが冷えた会話に送信したりすると、5 時間の上限の目立つ割合を使う場合に Claude Code が警告します。そのまま再開するか、新しい会話を始めるかを選びます。表示されるのは Anthropic がプランとモデルごとに設定した最小割合からなので、多くのモデルでは非常に大きな会話でしか表示されません。ガードの休眠中の質問は 15 万トークンから行うため、冷えた再開の多くをカバーし、最大規模では両方が表示されることがあります。

## コマンド

```text
/agent-guard [status]                          ガードが今見ているもの
/agent-guard allow [agents|context] [minutes]  このセッションで制限を解除する（デフォルト：すべて、10 分）
/agent-guard pause [minutes]                   allow と同じだが、すべての制限に対して
/agent-guard resume                            allow を早期に終え、エージェントの一時停止を解除し、拒否された質問を再び尋ねられるようにする
/agent-guard report [days]                     このマシンでの動作（デフォルト：7 日）
/agent-guard simulate <rule>                   実際に保留したり消費したりせずに、ルールの動作を示す
/agent-guard help                              これらのコマンド
```

`/agent-guard` はターン途中でも即座に実行され、モデルのターンを開始しないため、Claude は上書きを目にすることも、それを許可と受け取ることもありません。制限を解除できるのはあなただけです。別のプラグインが `/agent-guard allow` や `pause` を実行すると、ガードは拒否し、その旨をトランスクリプトに表示します。以前のバージョンの目印だった `[allow-usage-guard]` や `[allow-agent-burst]` だけをプロンプトとして送っても、`/agent-guard allow` や `allow agents` と同じ結果になります。

## 確認できること、できないこと

Claude Code v2.1.316 で確認済み：

| パス | 対応範囲 |
|---|---|
| サブエージェント、チームメイト、ワークフローエージェント | 開始前に保留（`agent.spawn`） |
| `SendMessage` で新しい仕事を送られた完了済みサブエージェント | 再開前に保留し、開始として 1 回だけ数える |
| ディスクから呼び戻されたチームメイト（Claude Code 2.1.299 以降） | 再開前に保留し、開始として数える |
| `/subtask` のフォークや、`agent.spawn` なしで始まるものすべて | 開始時に数えるだけで、保留はしない。Claude Code がそれらより前にイベントを出さないため。Agent ツールから Claude が始めたフォークは他のエージェントと同じく保留される |
| Claude Code の内部エージェント（プロンプト提案、圧縮） | 数えない |
| プランウィンドウの割合 | サブスクリプションでは最後の API 応答から取得。`claude -p` でも同様。API キーのセッションでは取得できないため、トークンと回数の予算だけが適用される |
| 自分のターミナルペインで動いているチームメイト | 見えない。ループが別プロセスで動いているため |
| 他のマシン上のセッション | 数えない。セッション間の記録はこのマシンの mod ストアにある |
| API が自体で実行するツール（advisor など） | 保留できない。それらにはツールイベントが発火しない |

mod はターミナルの `claude`、デスクトップアプリの Code タブ、`claude -p`、Agent SDK で動作します。デスクトップアプリの WSL セッションでは動作しません（[mod が動く場所](https://code.claude.com/docs/en/plugins/mods/overview#where-mods-run)）。

**Team と Enterprise プラン**、および管理設定があるマシンでは、管理側の `prependPlugins` で除外しない限り、Claude Code は組み込みの `cc-plugin-sec-default` プラグインを他のすべてより先に実行します。このプラグインはユーザープラグインを通さずに Claude Code の古典的なフックイベントを送るため、Claude Code はガードについてスキップしたイベントごとに 1 行を表示します。例：「agent-usage-guard: its classic.PostToolUse hook was skipped」。ガードは、まだ届くイベントを通じて圧縮、ロックアウト、`/clear`、再開、そしてターンを開き直す Stop フックを追跡します。古典的なイベントが必要なのは 2 点あります：権限モードはエージェント開始時にしかガードに届かないため、`dontAsk` モードでも尋ねることがあること。もう 1 つは `/subtask` のフォークが数えられなくなることです。

**ネイティブの上限も依然として適用されます。** Claude Code は 1 セッションを 20 件の並列サブエージェント（`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`）と 3 層のネスト（`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`）に制限します。1 セッションが開始するエージェント総数には上限がありません。v2.1.316 以降、他に指定がない場合、サブエージェントが動く試行レベルを `CLAUDE_CODE_SUBAGENT_EFFORT` が設定します（セッションの値ではなく）。低くすればエージェントごとのコストが下がり、ガードは実行数の制限を続けます。ガードのデフォルトはより厳しくセッション横断的です。ガードが数えるだけのパスでは、ネイティブの上限が外側の壁として残ります。

## 実行内容を確認する

```text
/agent-guard report 30
```

レポートは、利用上限によるロックアウト（ロックされたウィンドウごとに 1 回）、プランウィンドウの閾値通過、収束注意書き、そしてルールごとの質問と拒否を、あなたの回答とともに数えます。このマシン上のすべてのセッションのジャーナルを読み、外には出ません。記録を止めるには `AGENT_GUARD_JOURNAL=0` を設定します。

## セキュリティとプライバシー

mod はあなたの権限で Claude Code 内で動作します。インストール前に[mod が触れるもの](https://code.claude.com/docs/en/plugins/mods/overview#what-a-mod-can-reach)を読んでください。これは依存関係のない約 3,000 行の TypeScript で、`claude plugin validate .` が呼び出すすべての API と読み取るすべての環境変数を列挙します：

- ネットワークリクエストもプロセス起動もしません。読み取るファイルは自分の `plugin.json` だけで、`/agent-guard status` が表示するバージョンのためです。
- 判定するのは上記のルールに書かれたことだけです：エージェントを開始するか、プロンプトを送るか、ツール呼び出しを実行するか。回答できるときは尋ね、拒否するときは理由を伝えます。権限モードは読み取りますが変更せず、設定も書き込みません。
- 送信するプロンプトはあなた自身のものだけです。「圧縮して、そのまま送信」を選ぶと、入力欄からあなたが打ったプロンプトを取り出し、圧縮完了後にそのまま 1 回だけ送ります。圧縮が失敗した場合は入力欄に戻します。画像や @ メンションを含むプロンプトは、再送すると失われるため、入力欄に残してあなたが送る形にします。
- プロンプトフックはあなたのプロンプトをそのまま通し、コンテキストが 300k を超えたりプランウィンドウが 95% に達したりしたときに一度だけ Claude 向けの注意書きを追加するか、プロンプトを保留して先に尋ねます（誰も回答できない場合は理由を伝えます）。`SessionStart` フックは何も変更しません。
- 状態は mod ストア、`~/.claude/plugins/store/` 配下の JSON ファイルに保持します。各セッションは自分の回数（実行中のエージェント、最近の開始と休眠中の再開、サブエージェントの 1 分あたりトークン、最新の 5 時間の使用率）、最後にアクティブだった時刻（30 日間保持され、再開時にどれだけアイドルだったかを知れます）、ジャーナルの行（時刻、セッション ID の接頭辞、ルール、ツール名、`400-500k` のようなコンテキスト区分、プランウィンドウと割合、拒否回数、あなたの回答）を書き込みます。各記録はセッションの完全な ID 配下に保存され、それはそのセッションのトランスクリプトファイルの名前でもあります。ストアが保存できなくなると（容量不足など）、ステータス行に表示され、他のセッションはこのセッションを数えなくなります。
- プロンプト本文、ツール入力、エラーの本文、モデルの出力は保存しません。API エラーでターンが終わった場合、会話の最後のメッセージ、つまり Claude Code が表示したエラーを読み、利用上限のロックアウトと他の失敗を区別します。ツール呼び出しは 13 文字のフィンガープリントに縮約されます。エージェント名はメモリに留まり、書き込まれません。
- 90 日より古いジャーナルは削除されます（`AGENT_GUARD_JOURNAL_DAYS`）。
- 上記の GIF を作る `demo/` は実行対象ではありません。架空の API キーで一時的な home ディレクトリの中で Claude Code を起動してスクリプト化されたローカル API を使うため、あなたの認証情報は読み取りません。

アンインストールせずに止めるには `AGENT_GUARD=0` を設定します。

## 設定

環境変数として、あるいは `~/.claude/settings.json` の `env` 配下に設定します。時間は秒単位です。数値でない値や範囲外の値はデフォルトのままになり、`/agent-guard` にその旨が表示されます。

| 変数 | 意味（デフォルト） |
|---|---|
| `AGENT_GUARD` | `0`、`false`、`off`、`no` でガードを無効化（`1`） |
| `AGENT_GUARD_JOURNAL` | `0` でジャーナルを停止（`1`） |
| `AGENT_GUARD_HAIKU_EXEMPT` | `0` で Haiku エージェントも他のエージェントと同じく実行中と開始数の上限に数える（`1`：除外する） |
| `AGENT_GUARD_JOURNAL_DAYS` | 保持するジャーナルの日数（`90`） |
| `AGENT_GUARD_WINDOW_SECONDS` | 予算、消費速度、拒否のローリングウィンドウ（`600`） |
| `AGENT_GUARD_AGENT_MAX` | このマシンで同時に動くエージェント数（`4`） |
| `AGENT_GUARD_ROLLING_MAX` | このマシンで 1 ウィンドウあたりに開始・再開されるエージェント数（`12`） |
| `AGENT_GUARD_AGENT_TOKENS_MAX` | このマシンで 1 ウィンドウあたりのサブエージェントトークン数（`10000000`） |
| `AGENT_GUARD_DEPTH_MAX` | メイン会話より下のエージェントの层数（`1`） |
| `AGENT_GUARD_LIMIT_ASK_PERCENT` | 新しいエージェントに尋ね始めるプランウィンドウの割合（`80`） |
| `AGENT_GUARD_LIMIT_DENY_PERCENT` | 新しいエージェント、ウェイクアップ、スケジュールジョブを拒否し、各セッションに収束を伝えるプランウィンドウの割合（`95`） |
| `AGENT_GUARD_BURN_PERCENT` | 新しいエージェントに尋ねる、1 ウィンドウあたりの 5 時間ウィンドウの上昇ポイント（`20`） |
| `AGENT_GUARD_CONTEXT_WARN` | ターンを限定するよう一度だけ Claude に伝えるコンテキスト量（`300000`） |
| `AGENT_GUARD_CONTEXT_HARD` | プロンプトを送る前に尋ねるコンテキスト量（`500000`） |
| `AGENT_GUARD_TOOL_CONTEXT` | ツール呼び出しがツール予算に数えられるようになるコンテキスト量（`400000`） |
| `AGENT_GUARD_TOOL_MAX` | そのコンテキストを超えたときの 1 ウィンドウあたりのツール呼び出し回数（`20`） |
| `AGENT_GUARD_DORMANT_SECONDS` | 重いセッションのキャッシュが切れたとみなすアイドル時間（`3600`） |
| `AGENT_GUARD_DORMANT_CONTEXT` | アイドルセッションが重いとみなされるコンテキスト量（`150000`） |
| `AGENT_GUARD_DORMANT_MAX` | 誰にも尋ねられないときの、このマシンで 1 ウィンドウあたりの重い休眠再開の上限（`1`） |
| `AGENT_GUARD_TOOL_FAILURE_MAX` | 同じ再試行を拒否するまでの一貫した失敗回数（`3`） |
| `AGENT_GUARD_FUSE_MAX` | 生成を一時停止するまでに拒否されたエージェント呼び出し回数（`5`） |
| `AGENT_GUARD_FUSE_SECONDS` | ヒューズの期間と一時停止の長さ（`600`） |
| `AGENT_GUARD_PEER_TTL_SECONDS` | 他のセッションの回数や、活動の兆しがないエージェントが有効とみなされる時間（`900`） |

休眠のデフォルトは、サブスクリプションがプラン利用量の範囲内で得られる 1 時間のプロンプトキャッシュを前提としています。API キーや追加利用分ではキャッシュは 5 分なので、`AGENT_GUARD_DORMANT_SECONDS=300` を設定してください。

## Claude Code の外へ

ルールは I/O を行わないハーネス非依存のコア（`core/`）にあり、Claude Code 用 mod はその最初のアダプターです。[docs/architecture.md](docs/architecture.md) に、アダプターが守る契約と、別のエージェントハーネスが各ルールを実現するために必要なことが書かれています。

## テスト

```sh
claude plugin validate . --strict
claude plugin test
```

`claude plugin test` は Claude Code 自身のテストキット内でスイートを実行します。コアのユニットテストと、セッション、モデル、ネットワークなしでフックモジュールを通して実際の Claude Code イベントを発火させるテストです。[TESTING.md](TESTING.md) に層と各テストが証明する内容がまとまっています。
