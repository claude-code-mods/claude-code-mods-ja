# agentctl — 1 つの Claude Code セッション用 Agent コントロールプレーン

**Claude Code 2.1.288**（ヘッドレス）と **2.1.289**（インタラクティブ、ホストの自動更新後）でテスト済み（`claude plugin validate .`、`claude plugin test .`：203 テスト）；0.2.x は 2.1.289 上でライブ再検証済み（§ 0.2.x ライブ検証）。
mods API はリリース間で変更可能とマークされており、ホストが書き込む `.claude-plugin/types/` の型宣言がインストール済みバージョンの権威です。Claude Code をアップグレードするたびに `claude plugin validate .` を実行してください。

設計：本リポジトリの `docs/features/agent-control-plane-mod/`（要件、実現可能性調査、技術仕様、要求チケット）。このディレクトリは sd0x-dev-flow プラグインの一部ではありません：プラグインのインストールは mod をインストールしません。インストールするには `/agentctl-setup` を実行します（ホストを確認し、承認後に `agentctl@sd0xdev-marketplace` をインストールし、最初のタスク行を構築します；`/agentctl-setup --task` とワークフロースキルは代わりに提案を起案してあなたに受け入れてもらいます）、または `claude --plugin-dir mods/agentctl` で 1 セッションだけ読み込みます。

> 日本語版は claude-code-mods-ja プロジェクトによる翻訳です。原作者とライセンスは文末に記載されています。原版の README は [README.en.md](README.en.md) をご覧ください。

## 初回実行

やっていることを入力してください — 他のコマンドは不要です：

```text
/agentctl 測試一下這個新功能
```

1. mod は Claude へのリクエストをプロンプト欄に置きます（送信はしません）。**Enter** を押します。
2. Claude はプロジェクトを読み、スコープ — 編集可能なもの、証拠となるチェック、"done" の意味 — を起案し、mod に同梱のヘルパー（`bin/propose.mjs`）で書き込みます。不明点があれば権限を捏造せず質問します。
3. その返信の末尾で mod がスコープを表示し、欄に `/agentctl accept <digest>` を提示します：**Tab**、続けて **Enter**。受け入れるとスコープが束縛されます；作業は開始しません。
4. Claude に開始を依頼します。`/agentctl` は進捗と次の手順 — チェックを実行し、その後 `/agentctl handoff` — を示し、`/agentctl help` が残りを列挙します。

設計を読まなかったテスターが手順 1–4 と引き継ぎを無指導で歩きました（§ 無指導実行）。

リクエストの送信は通常の Claude ターンです；mod 自身はモデルを呼びません。目標が中国語で書かれているときは返信は繁体字中国語、それ以外は英語 — 単純なヒューリスティックであり、ロケール検出ではありません。

## 何をするか

| 機能 | 方法 |
|---|---|
| タスクスコープ | Claude が提案を起案（`/agentctl-setup --task`、または mod インストール後 `/feature-dev`、`/bug-fix`、`/refactor`）；mod がプレビューし、自分のプロンプトで `/agentctl accept` と入力するとまさにプレビューされたものが束縛されます — § 提案 参照。プロンプトで `/agentctl task set <json>` と入力してもタスクを worktree に束縛できます。ツール出力、ファイル、メッセージでは変更できません — あなたが入力したコマンドだけが変更できます。束縛は worktree 単位なので、同じ worktree の別セッションで自分で `task set` / `task clear` を実行すると置き換えまたはクリアされます。タスク記録と引き継ぎは worktree 単位で保持されるため、2 つの worktree の同じタスク id は別々のタスクを指します。ストアエラーはその通り報告され、以前のタスクは適用され続けます；記録が欠落した束縛は worktree 内の読み取り以外すべてを拒否します |
| 拒否 | 拒否リスト。認識された直接の本番書き込みとリモート git 書き込みは **タスクの有無にかかわらず** 拒否されます；タスクが束縛されている間は、その `forbid` エントリと roots 外の編集も拒否されます。編集 roots は編集ツール（Write、Edit、NotebookEdit）を束縛します；shell リダイレクトで書き込まれたファイルは mod が分類できない Bash コマンドなのでホストに渡されます — 拒否は Claude に別の方法で同じ結果を得ないよう伝えますが、roots はサンドボックスではありません。mod が分類できないもの — スクリプト、複合 shell、未知のツール — は Claude Code 自身の権限プロンプトまたは auto モードに渡され、`delegated` として記録されます。下流の拒否は弱められず、許可も作成されません。**ベストエフォート**：mod は各ツール呼び出しを読みますが、スクリプトの内容や起動するコマンドは読まないため、スクリプト内の push はホストとそのワークフローが承認するものです |
| 証拠 | 宣言された `check` 実行器に一致する実行がカウントされます — まず語を優先するため、追加引数があってもカウントされますが宣言より少ないチェックになる場合があります；一方、パイプ、リダイレクト、ラッパー（`npm test \| grep pass`）はカウントされません。accept の返信と `/agentctl` は各チェックをそれに一致する行として、または — フォーマッタが 1 片で語を引用できないとき — その JSON 語として命名します。JSON 語はそのままコピーすると一致せず（同じ語の正しく引用された綴りなら一致します）。一致する呼び出しは Git 派生のツリー読み取りで囲まれます（実行器が先に一致するため、宣言された `git status` チェックもチェックです）；後の編集は 30 秒以内に結果を stale にします；バックグラウンドチェックは終端結果が見られるまで "completion unobserved" のままです。証拠は観測されたときのタスクとポリシーバージョンに属し、部分的なカバレッジの読み取りは検証済みとして列挙されません |
| パネル | プロンプト上のバンドはコンパクトです：タスク、ランタイムとその所要時間、必要なあなた、年齢付きのゲート読み取り（30 秒を超えると `stale`）、最後の引き継ぎ時刻。`/agentctl` はコンパクトな状態返信 — 次の手順、タスク、必要なあなた、ゲートと証拠；`/agentctl status --details` はストレージ健全性、ランタイム、コンテキスト、5h ウィンドウを追加します。ゲート、コンテキスト、ウィンドウ行はソースと年齢を名指しするか `missing` / `unavailable` と読み、各証拠行は結果、鮮度、カバレッジ、年齢を示します |
| 引き継ぎ | `/agentctl handoff` — 記録から 8 つの回答、モデルなし、ネットワークなし、プロセスなし；再オープン時に完全記録（トランスクリプトのみ）；裸の `/agentctl` はそれへのポインタのみ、`/agentctl last` が全体を印刷します |
| 停止 | `/agentctl stop` — 引き継ぎを保存し、現在のターンのキャンセルを要求し、追跡中の操作を列挙；"all stopped" とは決して言いません |

## 提案

Claude は mod の同梱 `bin/propose.mjs`（`/agentctl <目標>` パス）または sd0x-dev-flow の `agentctl-setup.js propose`（セットアップとワークフロースキル）を通じて `~/.claude/agentctl/proposals/<URI エンコードされた worktree>.json`（worktree の外）を書き込みます；どちらも mod 自身の検証を先に適用します。セッション開始時と各主ターンの終わりに mod は一度読み込み、再検証し、**有効**なオブジェクトを保持します：worktree はセッションから取られ、別の worktree を名指す提案、束縛が外れたタスクに対して起案されたもの、ビルトインクラスと重なるものは拒否されます（理由はログされます）。プレビューは SHA-256 ダイジェスト（24 桁 16 進）付きでトランスクリプトとバンドに受け入れられる各権限を列挙します。各エントリは 160 文字まで表示；長いものは `…` で終わりますが、ダイジェスト — および accept が束縛するもの — は全体をカバーするので、エントリ全体を見られない草稿は破棄してください。

| コマンド | 誰 | 作用 |
|---|---|---|
| `/agentctl proposal` | 誰でも | 待機中のプレビューを印刷 |
| `/agentctl accept [digest の接頭辞]` | **あなたのプロンプトのみ** | 束縛されたタスクがプレビュー以来変わっていなければ、保持されたオブジェクトを束縛 — ファイルの再読み込みは決してしない |
| `/agentctl discard` | 誰でも | 待機中の提案を破棄；束縛されたタスクは残る |

ファイルを後に変更すると新しいプレビューとダイジェストが生まれます；古いダイジェストはもはや一致しません。1 つの worktree 上の同時セッションは 1 つの束縛と 1 つのストアを共有し、セッション間で非原子です：プレビューを表示したセッションで accept してください。

## タスク JSON

```json
{
  "goal": "investigate the quiz service timeout",
  "allow": ["edit"],
  "editRoots": ["src", "tests"],
  "forbid": ["terraform apply"],
  "executors": [{ "argv": ["npm", "test"], "check": true }],
  "needsUser": [["npm", "publish"]],
  "tools": ["mcp__docs__search"],
  "acceptance": ["unit tests pass on the final tree"]
}
```

ビルトインの禁止クラスはタスクの有無にかかわらず適用され、タスク自身の上に重ねられます：本番書き込み（`kubectl apply|delete|patch|rollout|scale|edit|replace`、`helm install|upgrade|uninstall|rollback`、`gcloud … deploy|delete|update`）とリモート git 書き込み（`git push`、`gh pr merge`）。秘密はタスクに決して属しません：ポリシーフィールドに資格情報のような値があると拒否されます。

`needsUser` は人が回答しているのが見られた場所のみを尋ねます：`default`（手動）、`acceptEdits`、`auto` 権限モード下のインタラクティブ端末（`lib/verdict.js`）。モードは各プロンプトとツール終了時にクラシックフック入力から読み取られます；見られるまで、および他のすべてのサーフェスやモード — `-p`、`dontAsk`、`plan`、`bypassPermissions`、Desktop、VS Code、mobile — では `needsUser` 呼び出しは拒否されます。ターン途中で切り替えたモードは次のツール終了時に見られます。

## 何ではないか

- **隔離境界ではありません。** あなたの権限で動きます。本番読み取り専用は資格情報と対象の IAM/RBAC の仕事です。
- **唯一の防衛線ではありません。** ホストがフックをスキップすると（mod 無効、worker クラッシュ）ここでは何も拒否しません。名指しの危険コマンドは自分の `permissions.deny` に残してください、例えば：

  ```json
  { "permissions": { "deny": ["Bash(kubectl delete:*)", "Bash(kubectl rollout:*)", "Bash(helm upgrade:*)"] } }
  ```

  これらのルールはプログラムではなくコマンドテキストに一致します（`git -C . push` は別のテキスト）、だから両層が存在します。`Bash(git push:*)` は意図的に省略されています：sd0x-dev-flow の `/push-ci` が実行します。
- 別の mod は `tool.check` で判定を変更できます；本 mod は `/agentctl policy` で開示します。
- 認可された実行器（例 `npm test`）は影響を未分類のまま実行します。

## リリース

mod は独自にバージョン管理され、`agentctl-v<version>` タグでリリースされます（`.github/workflows/release-agentctl.yml`）、sd0x-dev-flow のリリースとは別です。Claude Code はインストール済みプラグインをバージョンでキャッシュするため、この README や `tests/` 以外の変更にはバージョンバンプが必要です：`.claude-plugin/plugin.json` の `"version"` を上げ、リポジトリルートから `node .github/scripts/agentctl-version.js update` を実行（または `/bump-version agentctl`）。両方が完了するまで CI のバージョンロックは失敗し、CI はここで `claude plugin validate` と `claude plugin test` も実行します。

| 手動モードのインタラクティブ端末での `ask`（V3） | 副本が `ask` に答える場合、ホストは mod の理由付きで自身の承認ダイアログを表示（Yes / No、"don't ask again" なし）；拒否すると呼び出しが中断；発行コードで再実行（手動：ダイアログ；`dontAsk`：mod が拒否）、および `acceptEdits` と `auto`（ダイアログ）および `dontAsk`（拒否）下の副本でテスト。ホストが送る文字列は通常のクラシック `UserPromptSubmit` フック（2.1.289）から読み取られました：`default`、`acceptEdits`、`auto`、`plan`、`dontAsk` はそれぞれ逐語で到達；auto モードのないモデル（Haiku）では `--permission-mode auto` は `default` にフォールバック |
| インタラクティブ開始（ライブで発見） | `session.start` と最初のバンド描画は同時に到達；2 つの同時コンテキストビルドがバンドを孤立コンテキスト（`gates missing`）に残しました。修正：共有ビルド 1 つ |

## 0.2.x ライブ検証（2026-10-05、スクラッチクローンとスクラッチ裸リモート、2.1.289、Haiku）

| チェック | 結果 |
|---|---|
| タスク未束縛時の直接 `git push`（`-p`） | 実行前に `remote-git-write` で拒否；リモートは空のまま |
| 未分類 `python3 -c …` と push するスクリプト（`/bin/bash -p push.sh`、`-p`） | どちらもホストに渡って実行；スクリプトの push は git に到達（スクラッチリモート自身に拒否された、mod ではない） — 開示済みのスクリプト盲点 |
| `agentctl-setup.js propose` による提案、インタラクティブ開始 | プレビューはセッション開始時にヘルパーのダイジェストでログされ、バンドは待機中の提案を名指し |
| プロンプトで `/agentctl accept <digest>` | プレビュー範囲を新タスクとして束縛；`base` なしではヘルパーはダイジェストを印刷せず、mod が束縛済みタスクを埋め、自身のダイジェストが受け入れられた |
| 宣言済みチェック、未分類呼び出し、roots 外編集、直接 push（束縛タスク） | チェックは `current` 証拠として記録；`python3` は委譲され `/agentctl events` にそう列挙；編集は `edit outside the allowed roots` で拒否；push は `remote-git-write` で拒否 |
| 外部から追加された未追跡ファイル | 32 秒以内にチェックが `stale (tree changed since)` を読む |
| `/agentctl handoff`、再オープン、`/agentctl`、`/agentctl last` | 引き継ぎはツリーをいつ読んだかを述べ、"未検証" の下にその stale チェックを列挙；再オープン時にトランスクリプトに表示、裸 `/agentctl` はポインタ行 1 行、`/agentctl last` は全体を印刷 |
| 0.2.1 でライブ発見・修正 | 受け入れ済み提案ファイルが次のセッションで陳腐な草稿として再読み込み（現在は worktree 単位で記憶）；ビルトイン拒否は "そのタスクのスコープ" と言った、Claude はその後タスク拡大を提案（現在："タスクが解除できないビルトインクラス"）；トランスクリプト行は `agentctl: agentctl:` と読む |
| 2 つの `-p` プローブのコスト | 各 2–3 ターン、Haiku で各約 $0.06；mod 自身の返信、プレビュー、バンドはモデルを呼びません |
| 独立敵対テスト（Codex、2026-10-05）、0.2.2 で修正 | 絶対または大文字プログラムパス（`/usr/bin/git push`、`GIT push`）がビルトインクラスをすり抜けた；編集 root が `../other` だと worktree 外への書き込みを認可；提案上限は文字数ではなく UTF-8 バイトを数えていた；タスク未束縛時に委譲呼び出しが `/agentctl events` に記録されなかった。ダイジェスト一致、プロトタイプキー、他 worktree 拒否、証拠分割、部分カバレッジは成立 |

## 0.3.0 ライブ検証（2026-10-07、スクラッチクローンとスクラッチリモート、インタラクティブ tmux、Haiku）

Signal 13、2.1.289（手順 1–3）で歩き、2.1.292 から最初から再び：

| 手順 | 結果 |
|---|---|
| `/agentctl 幫 …/README 加一行測試說明` | 空欄が繁体字中国語でヘルパーパス（`$.plugin.root` から）とともに埋まった；送信も束縛もされない |
| Enter | Claude はヘルパーの `--help` を実行し、プロジェクトを読み、ファイルが無いことを発見し、スコープを捏造せず **質問** した；回答後ヘルパーで提案を書き込み |
| プレビュー | ダイジェストと "スコープのみを束縛；作業は開始しない" とともにターン末に表示；バンドは待機中の提案を名指し |
| Tab + Enter | 提案から受け入れ；返信は次の手順を名指し |
| "作業を開始" | 受け入れた roots 内の編集はホスト自身の権限プロンプトへ；宣言済みチェックは current 証拠として記録 |
| `/agentctl`、`handoff`、再オープン、`last` | 状態は次の手順を先頭に；引き継ぎはそのチェックを検証済みとして読み取り時刻とともに列挙；再オープンはそれを指し、`last` が印刷 |
| 束縛タスク時の 2 つ目の目標 | ヘルパーは束縛タスク下で配達；プレビューは "置換：タスク …" と言った；Tab + Enter で置換 |

歩き中に発見・修正：2.1.292 ではホスト自身の次プロンプト推測（"確認"）が欄を取ったため、Tab + Enter はその語を Claude に送ったであろう — mod は現在、提案が待機中はホストの推測を accept 行で置き換え、各ターン末に再提示します；accept 返信の最終行は中国語セッションでも英語のまま；タスク束縛時、埋め返信は "何も束縛されていない" と言いました。記録された躊躇：Claude は一度 worktree 外の mod 自身のファイルを読もうとした（ホストプロンプトで却下）；コピーランゲージは新しいセッションごとにリセットします。

## 無指導実行、0.3.0（2026-10-07、Codex が初回ユーザー、インタラクティブ tmux、使い捨てクローン）

テスターに与えられたのは `/agentctl <やっていること>` のみで、`docs/` も本 mod のコードも読んでいません。記述 → Enter → プレビュー（約 72 秒、README のみのスコープ、3 チェック）→ Tab + Enter → "作業を開始" → `/agentctl` → `/agentctl handoff` が外部支援なしの 6 手順で完了。そこから発見し 0.3.1 で修正：

| 発見 | 0.3.1 |
|---|---|
| README が変更されているのに引き継ぎが "Edits observed: 0" と読む（Claude は Bash 経由で編集） | その行は編集ツール呼び出しを数え、Bash の変更はツリー行にあると言います |
| Claude がテストを `grep` 経由のパイプで実行；引き継ぎはチェックを stale と呼び、Claude は通過と呼んだ | accept 返信は逐語で実行するチェックを名指し；`/agentctl` は名前で再び要求 |
| 作業完了後も `/agentctl` が "Claude に作業開始を依頼してください" と言った | 次の手順は宣言済みチェックに従います：作業して実行、非 current を再実行、または引き継ぎ |
| roots 外の Write が拒否され、その後同じファイルが Bash heredoc で書き込まれた | 拒否は Claude に別の方法で結果を得ないよう伝えます；この節と § 何をするか は roots が編集ツールのみを束縛することを述べます |
| Claude が質問し、同じターンで提案を書いた | 起案リクエストは回答を待ってから書くよう指示します |

そのままにした点：クローン自身の `CLAUDE.md` がドキュメント変更に 2 ラウンドのレビューを要求するため実行に数分かかったのであり、mod のせいではありません。
