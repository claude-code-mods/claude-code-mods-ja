# Claude Code 用 Cache Tax

> 日本語版は claude-code-mods-ja プロジェクトによる翻訳です。原作者とライセンスは文末に記載されています。原版の README は [README.en.md](README.en.md) をご覧ください。

**あなたが離れている間に Claude Code のプロンプトキャッシュを温かく保ちます。**

Cache Tax は、あなたが席を離れている間にプロンプトキャッシュを更新し、コールド送信の前に推定される書き換えコストを示す Claude Code mod です。休憩前に `/keepwarm 90m` を実行してください。ping はトークンを消費します；戻ってくる予定の時間を選んでください。

**[インストール](#インストール)** · [ウェブサイト](https://cachetax.aidojo.si/) · [仕組み](#仕組み) · [コストとプラン上限](#コストとプラン上限の問題) · [コマンド](#コマンド)

![cache-tax が $6.61 の推定値でコールド送信を止めた実際の録画](https://github.com/karanb192/cache-tax/raw/main/site/assets/refusal.gif)

330k トークンのセッションで、2 行の要約が **$6.61 の推定値** を引き起こしました。再送後、報告されたキャッシュ書き込みは **$6.28** でした。2.1.1 で録画；現在の文言では推定トークン数に「最大」と付きます。これらは API 換算のコストであり、追加のサブスクリプション料金ではありません。

## インストール

[Claude Code 2.1.287 以降](https://code.claude.com/docs/en/plugins/mods/overview#turn-mods-on-or-off)、1 時間のキャッシュ、Claude Code の実行中継続が必要です。mod は既定で有効です。ping は出力の上限なしを含めトークンを消費します。

```sh
claude plugin marketplace add karanb192/claude-code-mods
claude plugin install cache-tax@claude-code-mods
```

Claude Code を再起動するか、開いているセッションで `/reload-plugins` を実行してください。早期アクセスフラグは不要です。以前 `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` を設定していた場合は削除してください；現在の Claude Code は無視します。

温かいセッションで `/keepwarm` を実行すると 6 時間が起動されます。短い場合は `/keepwarm 90m`、停止するには `/keepwarm off` を使います。

**メインキャッシュの寿命を確認してください。** サブスクリプション利用の既定は 1 時間です。API キー、利用クレジット、クラウドプロバイダーのセッションは既定で 5 分なので、その課金経路では [`promptCacheTtl`](https://code.claude.com/docs/en/prompt-caching#choose-the-ttl-yourself) を `"1h"` に設定してください。50 分のタイマーでは 5 分のメインキャッシュは守れません。fork の根拠は[制限](#制限)を参照してください。

**settings hook 版を希望しますか？** [hook 版](https://github.com/karanb192/claude-code-hooks/tree/main/plugins/cache-tax) は既定で警告のみ、`CACHE_TAX_BLOCK=1` で 1 回拒否し、独立したステータス行カウントダウンを備えます。ウォーム維持は本 mod の機能です。

開発者：[Karan Bansal](https://karanbansal.in/)。[Cache Tax の経緯と計測済みのキャッシュコスト](https://karanbansal.in/blog/cache-tax/) もどうぞ。

## オプション

`/config` の cache-tax の下：

    Auto keepwarm:    on | off
    Display:          band | status
    Ping floor:       2 (数値、0 以上)
    Headless prompts: guard | send

`on`（既定）は従来の動作を保ちます：コールドキャッシュ書き込みを支払った後、keepwarm が 3 時間起動されます。`off` はあなたが `/keepwarm` で起動するまで何もしません；このときガードの文言は keepwarm がオフのままであること、または起動したウィンドウの残り時間を述べます。どちらでも `/keepwarm always` は起動し続けます。

Ping floor は、推定されるコールド再書き換えコストを休憩中のアイドル予算に割り振ります：2 なら推定 ping 費用が再書き換えの半分未満まで許容され、0 は制限を無効化します。ping の前に、この休憩で既に観測した支出と次の ping の推定値の合計が予算未満である必要があります。推定には直近 5 回の温かいレシートのうち最も安いものを使い、現在のモデルとコンテキスト（プロンプト tier を含む）で再計算します。新しい主ターンは支出をリセットしますが、ウィンドウの延長や停止・再起動ではリセットされません。スキップされた ping ではキャッシュが冷えるままになります。ログと状態に理由が示され、`$.cacheTax.status()` が `pingSkipped` と `idlePingUsd` を公開します。

最初の ping はレシートがないので送信されます。後の回答は推定より高くつくことがあるため、これは推定に基づく制限であり、請求額の上限保証ではありません。モデル価格、コンテキスト、価格付きレシートがなければ比較できません。レシートと支出はメモリ上にあり、再起動や新しい会話で消えます。ping は指定したウォーム期間の終わりより前に止まることがあります。

Display は keepwarm が起動されている間の表示場所を選びます。`band`（既定）はプロンプト上の行で、端末ではテキストアイコン、デスクトップでは立方体アイコン。`status` は同じテキストをプロンプト下のステータス項目に置き、行を描きません：別の mod がプロンプト上の領域を使う場合に選びます。非表示にする設定はありません：ping はトークンを消費するので、画面は常にその稼働を示します。

## 仕組み

**休憩前：** `/keepwarm` が有界なウィンドウを起動します。50 分アイドルすると、Claude Code 内部のタイマーがセッションのトランスクリプトに対してツールなしの fork を 1 回送ります。各 ping 後に使用量を読み、読み取りが 0 または書き込みが読み取りの 10% に達すると停止します。アイドル支出制限によりウィンドウ終了前に以降の ping がスキップされる場合があります。バックグラウンドのトランスクリプトポーリングループはありません。

**冷えた状態で戻ったとき：** 50,000 トークン以上のコンテキストでは、1 時間タイマーがコールドと判定したとき、通常のメッセージが送られる前にガードが尋ねます。質問には推定される再書き換えコストとウォーム維持の案内が表示されます。**とにかく送る** はそのメッセージを送り、**送信しない** は破棄します。ダイアログが閉じられたかホストが回答できない場合、ガードは 1 回拒否し、再送は通ります。ダイアログに答えられる SDK ホストはその選択を保持します。`/cache-tax guard refuse 5` は $5 以上で質問します（価格行のないモデルを含む）；それより安い送信は価格をログして進みます。

`Headless prompts: send` は非対話の `sdk` 起源プロンプトを既定のガード設定で即座に送信します。Claude Code は `claude -p` と Agent SDK ターンに同じフィールドを使うため、このオプションは両方を対象にします；CLI と SDK ホストの区別はできません。既定の `guard` は質問を続け、誰も答えられない場合は 1 回拒否します。明示的な `/cache-tax guard refuse`（金額下限の有無にかかわらず）は `send` でも効き続けます；`/cache-tax guard default` はその明示的な設定をクリアします。リモートの人間からのメッセージ（`composer`、`bridge`、`unclassified`、チャンネル起源）は非対話ホストでもガードを維持します。バックグラウンド通知とスケジュール済みプロンプトは、価格を記録して送信されます；再送できる人がいないためです。

ヘッドレスの拒否は理由を返し、トランスクリプト／デバッグログに記録します。スクリプトの診断には Claude Code の `--debug-file` を使ってください。mod API はプロセスの終了コードを設定したり、拒否を stderr に書いたりできません；拒否が非ゼロ終了や stdout の理由を伴うとは限りません。金額下限に達したオプトイン実行も、意図的に再試行する必要があります。

既定では、コールド書き込みを検出すると自動的に少なくとも 3 時間の keepwarm を起動し、always が有効なら常時ウィンドウ（設定しない限り 6 時間）を起動してコストを表示します；Auto keepwarm オプションで自動部分をオフにできます。`/cache-tax` は現在のキャッシュ推定、ウォームウィンドウ、このセッションのコールド書き込み累計を表示します。

累計はキャッシュレシートに従います。各リクエストについて、古いコンテキストが再書き込みされた量を「報告された書き込み」と「直前のコンテキストから報告された読み取りを引いた値」の小さい方として推定します。読み取りの 10% 未満の欠落部分はキャッシュヒットとして扱います。ヒット時の新規内容は計上されず keepwarm も起動しません；ただし実質的な部分書き換えは計上される場合があります。各書き換えにはそのリクエストのモデルと価格 tier を使います。

ホストが合計されたターン使用量のみを報告する場合、後続のキャッシュ読み取りに隠れた書き換えを見逃すことがあり、リクエスト単位のレシートがない圧縮済みターンは採点されません。

ガードが送信を許可したものの書き換えが検出されない場合、完了ノートは自動コールド書き込みウィンドウが開かなかった旨、または既存のウォーム状態を述べます。これは合計使用量からサーバーのキャッシュ状態を確認するものではありません。`/clear` で中断されたコールド書き込み完了は、置き換えられた会話で自動ウィンドウを開けません。

圧縮の準備やスキップはウォーム維持に影響しません。適用された圧縮は、主リクエストが新しいプレフィックスを読み取るか書き込むまで一時停止します。その後、起動されたウィンドウはターンがツールやユーザーの回答を待っている間に ping を再開できます。要約の書き込みは累計に入りません；圧縮前に支払った書き換えは元のコンテキストと価格を保持します。

ウィンドウは個々のセッションに属します。すでに冷えたセッションは次のターンまで ping しません。Claude Code の再起動後に復元されたウィンドウも、新しいプロセスが fork できるターンを持つまで待ちます。ping 対象が見つからない場合は 1 行の注記が一度表示され、次のメッセージ以降に ping が始まります。繁忙な API（429、529、5xx）で拒否された ping は、キャッシュが冷える前に届く間、1 分、2 分、4 分後に再試行されます。always が有効な場合、キャッシュに触れる各ターンは既定周期で常時ウィンドウ（既定 6 時間）を少なくとも残し、アイドル支出制限と温かい読み戻しの成功が条件です。`/keepwarm always 24h` はすべてのセッションについてこの下限を 24 時間にします（1h〜168h；引数なしの `/keepwarm always` は 6 時間に戻ります）。同じターンが停止したウィンドウを復活させ、短いウィンドウを常時ウィンドウまで延ばし、テスト周期をリセットします；あなたが設定したより長いウィンドウは保持されます。どのセッションでも `/keepwarm off` を実行すると、次のターンからすべてのセッションのロールが停止します。ウィンドウは期限で終わり；`/keepwarm off` はこれをキャンセルし always 設定もクリアします。

Sonnet 5、2026 年 9 月 16 日：状態は **75k トークンを $0.02 で読み取った** と報告しました。ライブ実行中に会話には何も表示されませんでした。このキャプチャは 2.0.0 の 1 分テスト間隔を使っており、カードの $0.45 という再書き換え推定は古い Sonnet 価格行に基づきます；現在の行では同じコンテキストが $0.30 です。2 セントの ping はそのセッションのレシートであり、固定価格ではありません。

## 短いメッセージが高くつく理由

キャッシュされたプレフィックスが失効すると、「要約して」という一文でも回答の前に古いコンテキストの書き換えが発生します。Cache Tax の Fable 5.1 の価格行では、100 万トークンあたり 1 時間書き込み $20 とキャッシュ読み取り $0.25 を比較しています：トークン単価で 80 倍であり、総節約額が 80 倍という意味ではありません。[価格の前提](#コストとプラン上限の問題)と [Anthropic の価格表](https://platform.claude.com/docs/en/about-claude/pricing) を参照してください。

[23 秒の概要を見る](docs/assets/cache-cost-explainer.mp4)。上演されたシーンには Fable 5.1 の定価が表示されます；端末とステータス行のピクセルはすべて上記の実録画とウォームレシートからのものです。拒否は 2.1.1、ウォームの切り抜きは 2.0.0 で記録しました。

キャッシュに慣れていませんか？[Anthropic が Claude Code での利用を説明しています](https://code.claude.com/docs/en/prompt-caching)。

## コマンド

    /keepwarm              6 時間温かく保つ
    /keepwarm 90m          任意のウィンドウで温かく保つ、1m 〜 168h（2h30m、6h も可）
    /keepwarm always       各セッションを最後のターンから 6 時間後まで温かく保ち、セッション間で記憶
    /keepwarm always 24h   同上、最後のターンから 24 時間後まで（1h 〜 168h）
    /keepwarm 6h every 2m  2 分ごとに ping；テスト用ノブ、1m 〜 59m、このウィンドウ後は忘れる（always 有効時は次のターンで）
    /keepwarm status       ウォームウィンドウ、次の ping、最近のレシート
    /keepwarm off          停止し、ウィンドウを忘れ、always をオフにする
    /cache-tax             カード
    /cache-tax guard warn  価格を表示して送信（hook の既定）
    /cache-tax guard default
                           既定のガードに戻し、Headless prompts が非対話 SDK 送信を制御するようにする
    /cache-tax guard refuse コールド送信の前に質問し、Headless prompts: send を上書き
    /cache-tax guard refuse 5
                           $5 以上でのみ質問し、それ未満では価格を表示して送信
    /cache-tax guard test   次に送るプロンプトでキャッシュが冷えているかのように一度質問し、このセッションのコンテキストで価格を計算；テストは採点せず、実際に冷えたキャッシュへの送信は通常通り採点

`/keepwarm` は余分な語、無効な時間、上限外のウィンドウを、現在のウォームウィンドウを変えずに拒否します。起動時に無効或者過長な保存済み期限も破棄します。最初の ping の前に終わるウィンドウは、その旨を返信で伝えます。

質問の原文と、その下の **Send anyway ($4.01)** と **Don't send**：

    cache-tax: the prompt cache went cold 2h00m ago. Sending this re-writes up to 200,502 tokens at $20/MTok = $4.01 (a warm turn would have cost $0.05). Don't send saves $4.01; after Send anyway, keepwarm is armed for up to 3h00m. The cache read alone is about $0.05 per ping. Pings may stop sooner at the idle spending limit, leaving the cache to go cold. Send it anyway?

質問が閉じられたか、ガード付きヘッドレス実行で表示できない場合、代わりに拒否が現れ、再送は通ります：

    cache-tax: the prompt cache went cold 2h00m ago. Sending this re-writes up to 200,502 tokens at $20/MTok = $4.01 (a warm turn would have cost $0.05). Send it again to pay it, and keepwarm will be armed for up to 3h00m, but may stop sooner at the idle spending limit. Or /clear and start from a note.

この数字は上限です。再開されたセッションについてエンジンが報告するコンテキスト数は、最後の応答の入力、キャッシュ読み取り、キャッシュ書き込み、出力の合計で、再開ペイロードには差し引くべき出力数が別にありません。15 日前のセッションでガードは 330,316 トークン、$6.61 と言い、その後の書き込みは 314k トークン、$6.28 でした。

keepwarm が起動されている間、端末とデスクトップの Code タブは Display が `status` でない限りプロンプト上に 1 行を表示します。端末は状態色の太字 `[>]` テキストアイコンを使います。デスクトップは Cache Tax の立方体を表示し、温かいときは蓋が緑、冷たいときは橙、最初のターン前や圧縮後は灰色です。太字の状態ラベルも同様です；タイマーとレシートのテキストは通常の太さです。空でない `NO_COLOR` は両サーフェスで太字テキストアイコンを選び、状態色を外します。どちらの表示でも `warm`、`cold`、`unknown` を表示するため、色だけが手がかりになることはありません。これらの状態は `/cache-tax` と同じ 1 時間タイマーを使い、実際のサーバーキャッシュ確認ではなく推定です。

その行とプレーンなステータス代替は、keepwarm が起動されている間はアイドル時も 1 分ごとに更新されます。更新は表示のみで、モデルリクエストは送りません。

その行にはウォームウィンドウ、次の ping、最近の読み戻しが含まれます。停止したループは中立の記号とその理由を表示します。`/keepwarm off` や期限切れで行は消えます。アンケートが一時的に優先され、他の mod の内容はバンドに残ります。Display `status` は同じラベル付きテキストをステータス項目に表示します；バンドのないサーフェスでは Display が `band` のままだとプレーンなステータステキストが残ります。

デスクトップの立方体と端末のコールド状態色は Claude のライト／ダークテーマに従います。埋め込み SVG はウェブサイトの公式アセットから来ており、保守者は `python3 tools/generate-status-icons.py` で再生成できます。実行時に画像ファイルを読み取ったり取得したりすることはありません。

mod はセッション開始時にテーマと `NO_COLOR` を一度読みます。受け入れられたテーマ変更はアイコンを即座に更新しますが、通常の再描画ではどちらも再読み込みしません。セッションを始める前に `NO_COLOR` を設定してください。

## 両方がインストールされている場合

hook と mod は名前も役割も共有するため、両方があるとコールド送信ごとに 2 つのガードが働きます。mod はセッション開始時に hook の `/cache-tax:status` コマンドが存在するか確認し、一度だけ知らせます。ガードは 1 つにしてください。settings hook を好む人には hook が選択肢として残ります。アンインストール前にステータス行を確認してください：`cache-tax.js` に結びついた 🧊 行は hook のファイルによるものです。本 mod は keepwarm が起動されているときにプロンプト上に描画し、シェルのステータス行を置き換えるものではありません。

## どこまでアクセスするか

Claude Code 2.1.312 で検証済み：

    ❯ ./register.ts hooks: config.set{key=theme}, ui.render{component=AbovePrompt}, session.start, session.end, classic.SessionStart, command.run{command=keepwarm}, command.run{command=cache-tax}, prompt.submit, turn.step, turn.complete, session.compact
    ❯ ./register.ts calls: $.clock.after (via arm, ping), $.clock.every (via updateStatus), $.clock.now, $.command.list, $.command.register, $.config.list, $.env.get, $.model.fork (via ping), $.session.id (via reseat, seat), $.session.model, $.session.usage, $.store.delete, $.store.get, $.store.set, $.ui.ask (via ask), $.ui.invalidate, $.ui.log, $.ui.resolve, $.ui.status
    ❯ ./register.ts env reads: NO_COLOR

到達レベル L2、Claude を駆動します。あなたが入力するすべてのプロンプト、すべてのモデルリクエストのタイミング、すべての回答のトークン数を見ます。

同じスキャン結果が [Awesome Claude Code Mods の cache-tax ページ](https://mods.aidojo.si/mods/karanb192--cache-tax--cache-tax/) にあり、何千もの他の mod がどこまでアクセスできるかを記録しています。

    cache-tax の脅威モデル（到達レベル L2、Claude を駆動）
    1. 読み取り：各プロンプトがスラッシュだけで始まり他に内容がないか（テキストはそのまま渡され、保持も記録もされない）；時刻；ターン完了時と fork 応答時にエンジンが既に持つトークン数とモデル id；Claude Code が settings hook 用に計算する再開フィールド；コマンド一覧；このプロセスの実行中、セッションごとに一度の session id、セッションのモデルとエンジン自身のコンテキスト数・開始時刻、さらにコールド送信の価格計算時と各 ping 前にモデルを再読；/clear やプロセス内再開で終わった会話の理由と session id；各主リクエストのメッセージ数；自身の $.store から session id でキー付けた keepwarm 期限と ping 周期、グローバルな always スイッチ（とそのウィンドウ）、金額下限付きガードモード；ロード時に Auto keepwarm、Display、Ping floor、Headless prompts の各オプション；セッションが対話的に始まったかどうか
    2. 実行：keepwarm ウィンドウ内のアイドル期間ごとに 1 回の $.model.fork、各 ping 周期ごとに 1 回（テストノブが設定しない限り 50 分、下限 1 分）、ウィンドウ外では決して実行せず、mod が既にコールドと知るキャッシュには決して送らず、何も読めなかったか読み取りの 10 分の 1 以上を書き込んだ読み戻しの後は決して実行しない；価格とレシートが分かっている場合、観測済みのアイドル支出と次の推定 ping の合計が再書き換えコストを Ping floor で割った値（0 は制限無効）未満のときだけ実行；コールド送信の前に Claude Code 自身のダイアログで 1 回質問するか、`/cache-tax guard test` 後の次のプロンプトで質問
    3. 送信：fork 以外は何もこの機械から出ない — fork は固定の 1 行プロンプトでセッション自身のトランスクリプトに対する API リクエスト
    4. 永続化：$.store にこのセッション id で keepwarm 期限と ping 周期（always 有効時は各ターン後に書き換え）、すべてのセッション分の always スイッチ（true またはミリ秒のウィンドウ）とガードモード（金額下限がその代わりに保存される）；拒否後はこのセッション id で最後の応答時刻を保存し、新しいプロセスからの再送（claude -p はターンごとにプロセスを起こす）を通す — 再送または /clear が削除；終了したウィンドウは停止時とこのセッションの次回起動時に、2.1.0 ストアの裸のキーとともに削除；他セッションのキーはここでは決して削除しない — 「読み取ってから削除」はそのセッションのウィンドウ更新と原子化できないため、keepwarm を起動して戻らなかったセッションは小さなキー 2 つを残す；セッションのコールド書き込み累計、最大 5 件の温かい ping レシート、アイドル ping 支出はメモリにありプロセスとともに消える
    5. 敵対入力：解析するテキストは 2 つのコマンドの引数だけで、時間の正規表現、金額、いくつかのリテラルに照合；ダイアログの回答は自身の 2 つのラベルとだけ比較；プロンプトテキストは先頭の非空白文字がスラッシュかどうかだけを見る；ツール結果とファイルが分岐に到達することはない；fork のプロンプトは定数なので、細工した内容をそこから送ることはできない；ガードが捨てるのはユーザー自身のメッセージだけ — 「送信しない」の後は再送について再度質問し、閉じられた／回答不能な質問の後は再送が無条件；hook が例外を投げるとエンジンはそれを飛ばしてメッセージが無ガードで入り、薄い 1 行が付く

## コストとプラン上限の問題

価格は定価表のもの：Fable 5.1 は 100 万トークンあたり読み取り $0.25、1h 階層の書き込み $20、回答 $50；Fable 5.2（$0.20、$16、$40）と Sonnet 5（$0.20、$4、$10）はそれぞれ独自の行を持ちます。価格が付くのは表に載っているバージョンだけ：表より新しいモデルは金額が `n/a` と「まだ価格行がない」旨の 1 行を表示し、古いモデルのレートを借用することはありません。API キーでは計算は単純です。ping はキャッシュ読み取り、自身の少量の未キャッシュトークン（基本レート）、モデルが返す内容（出力レート）が請求されます；表示される ping コストはすべてを含む。fork には出力上限がなく、高 effort のモデルが「warm」と言う前に考えることがあるためです。失効後の復帰は書き込みです。カードは選択したモデルについて読み取りのみの上限（Fable 5.1 では 80 回の ping）と現在の ping 周期でカバーできるアイドル時間を表示します；実際の ping は読み取りより少し高くつくため、真の损益分岐点はその数字より下です。サブスクリプションではドルは物差しであって請求書ではありません。キャッシュ読み取りが 5 時間と週次の上限にどう換算されるかは、私の探せる範囲ではどこにも文書化されていません。最初のウィンドウ中にステータス行のレート制限行を見てください。

## 制限

- mod には Claude Code 2.1.287+ が必要です。既定で有効ですが、ローカル設定、セーフモード、組織ポリシーで読み込めない場合があります。[mod の制御](https://code.claude.com/docs/en/plugins/mods/overview#turn-mods-on-or-off) を参照。
- 50 分のスケジュールには 1 時間のメインキャッシュが必要です。サブスクリプション利用では既定で備わります。他の課金経路では [`promptCacheTtl`](https://code.claude.com/docs/en/prompt-caching#choose-the-ttl-yourself) を `"1h"` に設定してください。
- 既定間隔でトランスクリプト検証済みの復帰、Fable 5.1 サブスクリプション、2026 年 9 月 19 日：`/keepwarm` は休憩 42 分目に起動し、ping は 50 分目に発火して 157k を読み、62 分目に送られたメッセージはキャッシュから 156,886 トークンを読み、2,255 を書き込みました。Claude Code 自身のキャッシュカウントダウンは ping 後に 58 分へリセットされ、fork が 1 時間の TTL を運んだことを示します。1 回の実行、1 つの構成：これは ping がそのキャッシュを 1 時間以上生かしたことを示し、すべての構成で純粋に得をすることを示すものではありません。Claude Code は fork を非メインリクエスト枠（通常 5 分）に分類しています。この実行では fork が 1 時間のセッションプレフィックスを読み、ネイティブのカウントダウンをリセットしました。これは 1 構成での観測行動であり、全プロバイダーが枠を同じに扱う証明ではありません。
- 温かく読み取れた ping は、その時点でキャッシュが温かかったことを証明します。プレフィックスの変更は時間にかかわらずキャッシュを無効化し得ます。正確な影響はモデルと Claude Code が変更を適用する時点に依存します；[Claude Code のキャッシュ動作](https://code.claude.com/docs/en/prompt-caching) を参照。
- 再開フィールドにより、ガードは再開後の最初の通常送信を確認できます。それらのフィールドがない場合、最初のターンがタイマーとコンテキストを種蒔きします。
- Team と Enterprise アカウントでは、管理対象プラグインが本 mod の上に着座してクラシックイベントと圧縮を処理し、その下に流し続けるため、これらは本 mod に届きません。そのため、`/clear` はセッション終了から知って keepwarm を停止させ、新しい会話は独自のウィンドウを得ます；再開されたトランスクリプトのコンテキストはエンジンの数字から知るが最後の応答時刻がなく、そのトランスクリプトの最初の起動から 1 時間経つと最初のメッセージは拒否ではなくコールド送信のコストを記録します；圧縮は直前リクエストの半分未満のメッセージ数のリクエストから判定し（rewind は数本を減らし、要約は数十本を置き換える）、圧縮からそのリクエストまでの ping や送信は古いコンテキストを見たままになります。圧縮後に書かれた要約はコールド書き込みとして計上されず、同じターンで圧縮前に支払ったコールド書き込みは（ホストがリクエストごとに使用量を報告する場合）計上されます。プロセス内再開を通じたウィンドウは新しいセッションのキーへ移ります。
- ガードのトークン数は上限です：エンジンが最後の応答に報告したコンテキストであり、再開時にはその応答の出力が含まれますが、差し引くべき出力数は mod にありません。
- コールド書き込み累計はセッション単位でメモリ上にあり；`/clear` で空になります。
- コンテキストサイズはエンジンのライブウィンドウ数です。ターン自身の使用量は各応答の合計で、10 ステップのターンではコンテキストを 10 回読み取ることになるため、ホストがライブ数を報告しない場合の代替にすぎません。

## 自分のセッションで確かめる

モッククロックのテストはタイマー、ガード、採点を証明するもので、fork がメインキャッシュに当たることは証明しません。それを証明するのは 1 回の ping で、そのコストはキャッシュ読み取り 1 回と回答です。温かいセッションで：

    > 一言で返してください: ready
    > /keepwarm 1h every 1m

1 分後にプロンプト上の行、または Display が `status` のとき／バンドのないサーフェスではステータス項目を見てください。`last ping read 20k $0.01` は fork の読み戻しを報告します。`keepwarm stopped: the ping read ... and wrote ...` は読み戻しが温熱しきい値に達せずループが停止したことを意味します。`API busy, ping retry 1 of 3` は 429、529、5xx を再試行中で、3 回後も繁忙かキャッシュが冷える 1 分前なら停止します。`nothing to fork yet` は再起動後のようにプロセスに fork できる会話がないことを示し、ウィンドウは次のメッセージを待ちます。他の API エラー、中断、空の応答は理由を付けてループを停止します。null を返す古いエンジンでは、コールドスナップショット／API 失敗の複合メッセージが表示されます。最後に `/keepwarm off` で終えてください。この短い確認はキャッシュ読み取りを証明するもので、既定 50 分間隔での保持を証明するものではありません。

## テストと型チェック

リポジトリルートから実行：

```sh
claude plugin validate .claude-plugin/plugin.json
claude plugin test .
```

[366 のテスト](tests/register.test.ts) はモッククロックとエンジンを使い、次をカバーします：

- **Auto keepwarm オプション：** off は支払済みコールド書き込みを採点するが keepwarm を起動せず、拒否と質問でその旨を述べる；手動で起動したウィンドウは期限まで守って ping を続ける；always は 6 時間の更新を続ける。
- **Ping floor オプション：** 累計支出が長い休憩を止め、主ターンがリセットし、再起動ではリセットされず、直近の安いレシートが高価な外れ値の後も残り、モデル切替が次の ping 前に価格付けされ、モデル読み取り中の off コマンドがその ping を取り消す。停止をまたいで請求された ping はカウントされ、ターン後に完了するものはカウントされず、エラーになったターンはスキップを保持。既存のスキップ、圧縮、クリア、未知コンテキスト、制限無効のカバレッジも残る。
- **Headless prompts オプション：** 非対話 SDK プロンプトのオプトイン、SDK ダイアログ回答、対話 SDK とリモート人間のガード、明示拒否と金額下限、既定への復帰、保存済み設定の読み込み中に届くプロンプト。
- **ガード：** Send anyway / Don't send の質問、閉じられたときの代替とガードテスト、1 回拒否して再送（新しいプロセスから、および応答のない API エラーの後も含む）、warn モード、金額下限（未満、一致、価格のないモデル、前ターンからの切替）、スラッシュコマンド、小さなコンテキスト、誰も入力していないプロンプト、再開時の種蒔き、コールド書き込みの採点。
- **ウォーム維持：** コマンドの既定値と拒否されるウィンドウ・周期、always/off、always と固有ウィンドウおよび拒否するウィンドウ、`/clear` 後の always、最終ターンからのロール、アイドルリセット、使用量による停止、コールドウィンドウの期限切れ、睡眠後の遅延タイマー。
- **セッション状態：** 分離された store キー、復元ウィンドウ、旧版の清理、clear／圧縮リセット、サブエージェントの分離。自動ウィンドウのタイマーや store 待機中の clear は、次の会話を起動したりその手動ウィンドウを消したりしない。
- **圧縮準備：** 要約の準備やスキップはウォーム維持を変えない。適用後、キャッシュを読み書きする主応答が、ターンがツールやユーザー回答を待つ間にウォーム維持を再開させる。要約書き込みはコールド書き込み累計に入らず、clear、停止、より新しい圧縮後の失敗リクエストや古い応答は ping を再開できない。
- **mod 上の管理プラグイン：** クラシック／圧縮イベントがユーザー層の下を流れる `/clear`、再開、復元ウィンドウ、圧縮；同じイベントの二重または順序違反の配送で 2 つ目のウィンドウ・警告・リセットが起きないこと；プロセス内再開で運ばれるウィンドウとモデル変更；再開後に十分古くなって冷えたトランスクリプト；rewind と圧縮の区別；コールド書き込みでない要約書き込みとコールド書き込みの併存（最初のリクエスト前に圧縮されたガード付き送信、1 ターン内の 2 回の圧縮）；クラシック再開と重なる／長く続く旧会話の終了；ホストが次の会話 id を報告する前に実行される `/keepwarm`。
- **価格と表示：** 載っているすべてのモデルの行を日付付き・プロバイダー・表示名の綴りで；表にないバージョンに借用行がないこと；価格行のないコールド書き込みをドル合計とは別に数える；Haiku 5.5 の長プロンプト階層をリクエストごとに価格付け；リクエスト合計でコンテキストの半分を書く長い温かいターンをコールド書き込みと分ける；ガード付きキャッシュヒットと大きな貼り付けは採点しない；部分書き換えを新規コンテンツと分ける；後の読み取りがリクエスト単位の未命中を隠せない；保持中のリクエストや clear 中のコンテキスト読み取りで古いレシートを捨てる；Opus 4 と 4.1 を Opus 4.5 と区別；出力と未キャッシュ入力のコスト、コンテキスト数、期間の書式、読み取りのみの損益分岐点の数字。
- **インジケーター：** 画像要素のない端末テキストアイコン、デスクトップ SVG、テーマ選択、温かい／冷たい遷移、再開、圧縮、clear、期限切れ、アンケート、他 mod の内容、`NO_COLOR` 代替。
- **Display オプション：** `band` は行を描く；`status` は cache-tax と状態ラベルを含むテキストを端末とデスクトップの行のないサーフェスのステータス項目へ移す。他の値（古い `off` など）は行にフォールバック。
- **設定：** セッションごとに 1 回読み取り、テーマ変更は即時、拒否された変更と設定書き込み器が返す有効テーマ。
- **fork 失敗：** 繁忙な API はキャッシュが温かい間に再試行、遅すぎる再試行は破棄、fork 対象なしは次のターンを待つ、同時に 1 つの ping だけ、リクエスト・`/clear`・圧縮の後に届いた応答は破棄、その他の失敗と古いリリースの null 結果は再試行せず停止。

描画テストは要素ツリーを調べるもので、ネイティブの端末・デスクトップのピクセルではありません。サーバー側のキャッシュ保持は検証しません。[ライブ確認](#自分のセッションで確かめる) を参照してください。

## 別の mod から状態を読む

cache-tax は mod API に読み取り専用の `$.cacheTax.status()` を追加します。これで状態バンドは `/cache-tax` を解析せずに keepwarm を表示できます。3.0 までは実験的で、フィールドはマイナーリリースで変わる可能性があります。`cold` は `/cache-tax` が表示するのと同じ 1 時間の推定で、サーバーキャッシュの確認ではありません。これは `{ keepwarm: 'on' | 'off' | 'stopped', leftMs, always, alwaysMs, autoWarm, guard, guardFloorUsd, cold, stopped, coldWrites, pingSkipped, idlePingUsd }` に解決します；型は `types/index.d.ts` にあります。cache-tax がインストールされていない環境には `$.cacheTax` がないので、呼び出し元は `try`/`catch` で包んでください。
