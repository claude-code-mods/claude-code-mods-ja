# Lot Map for Claude Code

`lot-map` は Claude Code の mod です。チャットの横にあるペインに、作業のライブマップを表示します。ツール呼び出し、モデルステップ、フック、スキルが発生するたびに、中心からそれぞれのステーションへパルスが飛びます。そのため、コマンドの一覧を読む代わりに、メモリ、ファイル、シェル、Web、エージェントが実際に動いている様子を見られます。

これはあなたのマシン上で動作し、どこにも何も送信しません。ローカルであることは盲目的であることを意味しません。ツール呼び出しを追跡する他の mod と同じように、各呼び出しは全体が渡されますが、mod がそこから取り出すのは名前だけです。[読み取り、保持するもの](PRIVACY.md) と [それを拘束するチェック](PRINCIPLES.md) を参照してください。

![The map during a work session](https://github.com/alexeyw/lot-map/raw/main/docs/demo.gif)

*架空のセッションを mod 自身の描画コードで再生したものです。[動画（MP4）](docs/demo.mp4)、あるいは [ブラウザで再生](https://alexeyw.github.io/lot-map/) できます。このページは同じコードを実行し、各呼び出しが mod に渡す内容と mod が保持する内容を表示します。*

## インストール

ターミナルセッションのプロンプトで、次を入力します。

```
/plugin install lot-map --marketplace alexeyw/lot-map
```

マーケットプレースの追加を求められたら `y` と答え、スコープを選びます。シェルからの場合：

```bash
claude plugin install lot-map --marketplace alexeyw/lot-map
```

「どのマーケットプレースにもプラグインが見つかりません」と表示された場合は、先にマーケットプレースを追加してください。

```bash
claude plugin marketplace add alexeyw/lot-map
claude plugin install lot-map@lot-map
```

デスクトップアプリでは、プロンプト欄の横の **+** をクリックし、**Plugins**、**Add marketplace** の順に選んで `alexeyw/lot-map` を入力し、**Add plugin** をクリックします。

ペインはセッション開始時に自動で開きます。`openAtStart` がオフの場合は `/lot-map` を待ちます。ターミナルでは幅が 144 列以上必要で、それ未満なら `/lot-map` を入力してください。特に指定しない限りテキストのみを描画します。マップを画像や点字ドットで表示する方法は [ターミナルでの表示](#in-a-terminal) を参照してください。macOS の Claude Code 2.1.321 でビルドとテストを行っています。Windows と Linux でも動作するとの報告があります。

Team または Enterprise のログインでは、トランスクリプトに `lot-map: its classic.PreToolUse hook was skipped` のような通知が出ることがあります。`guardedHooks` をオフにすると通知は止まります。その代わりにマップが失うものは [表示内容](#what-it-shows) を参照してください。

## 更新

シェルから実行します。

```bash
claude plugin marketplace update lot-map
claude plugin update lot-map@lot-map
```

その後、新しいセッションを開始してください。最初のコマンドが必要です。これを省略すると 2 番目のコマンドはインストール済みバージョンを最新と報告します。

各バージョンの変更内容は [CHANGELOG.md](CHANGELOG.md) にあります。

## 光るステーション

| ステーション | いつ |
| --- | --- |
| あなた | あなたのメッセージ、質問、あなたに送られたファイル、タスクリスト、プラン、承認を求められたもの |
| モデル | モデルへの各リクエスト、コンテキストの圧縮 |
| メモリ | Claude Code のメモリフォルダーと、オプションで指定したもの |
| ファイル | Read、Write、Edit、Grep、Glob、言語サーバーのコードインテリジェンス、およびファイルだけを扱うシェルコマンド。読み取り、検索、移動、削除、その場での編集（`cat`、`grep`、`mv`、`rm`、`sed`、`tee`、`find … -delete`） |
| シェル | その他のすべてのシェルコマンド |
| ネットワーク | Web のフェッチと検索、MCP サーバー、claude.ai 上に保持される作業（artifacts、projects、designs）、ネットワークに到達することが分かっているシェルコマンド：`curl`、`gh`、`ssh`、`rsync`、`git push`、`npm install`、`docker pull` など。`$(…)` の中も対象です |
| ブラウザ | ブラウザーツール |
| エージェント | サブエージェント、ワークフロー、スケジュール、バックグラウンド作業の待機。それぞれの呼び出しはこのステーションから始まります |
| スキル | スキル、ツール検索、スキル／プラグイン／コネクタのカタログ |
| フック | 呼び出しを拒否する、権限を求める、コンテキストを追加する、少し時間を取る設定フック |

Windows では PowerShell ツールも Bash と同じ方法で読み取られ、PowerShell 固有の名前が使われます。`Get-Content` と `Select-String` はファイルを、`Invoke-WebRequest` はネットワークを光らせます。フルパスで実行されたプログラムは名前で読み取られ、空白を含む引用符付きパスからも判定します。`CURL.EXE` は `curl` として扱われます。

シェルのステーションは、コマンドが実際に何をするかではなく、コマンド名で判定されます。例えば `python -c "…"` のように自ら接続を開くスクリプトはシェルとして表示されます。`sudo`、`env`、`timeout`、`nohup`、`xargs` などの後ろにあるコマンドは、実際に実行されるコマンドとして読み取られ、`find … -exec` は実行を指示されたコマンドとして読み取られます。ループや条件（`for … do`、`if … then`、`while`、`!`、`{ … }`）の中のコマンドや、シェルや `eval` に渡された行（`bash -c "…"`）も同様です。ヒアドキュメントの本文は読み取らないため、その中で書かれたファイルは内容にかかわらずファイルとして表示されます。1 行は先頭 8,000 文字まで読み取られます。`npx` は `-y` が付いた場合のみネットワークとして数えられます。これは `-y` がない場合、インストール済みのものを実行することが多いためです。

何かが始まるとパルスが飛び出し、終わると戻ってきます。拒否とエラーは赤くなります。

## マップの読み方

- **経路。** メインループが直近に通ったステーションを細い線が順につなぎ、新しい区間が描かれていきます。区間は 40 秒残った後 20 秒かけて薄くなり、作業が止まって 1 分経つとスポークだけが残ります。スポークの太さに、作業がどこへ向かったかが残ります。モデルステップは経路から省かれます。省かないとすべての区間がモデルを通ってしまうためです。
- **磨かれたスポーク。** ステーションが使われるほどスポークは太く明るくなり、セッション終了時には作業の向かった先が分かります。
- **長さ。** 呼び出しの実行中、ステーションの周りに 2 本の時計針が伸びます。内側は 1 分、外側は 10 分で一周します。
- **バックグラウンド作業。** バックグラウンドに送られたコマンド、モニター、バックグラウンドのサブエージェント、ワークフローは、それを開始したターンが終わった後もステーションが光ったままになり、時計針が進み続け、タスクが終了を報告するまで続きます。失敗したタスクは赤い点を残します。その報告自体はあなたのメッセージとしては表示されません。
- **同時に複数。** 同時に始まった呼び出しは並んで飛び、ステーションに `×3` のような数が表示されます。
- **何が起きたか。** エラーや拒否による赤い点が、次のあなたのメッセージまでステーションに残ります。
- **メモリ。** メモリには独自の色があります。塗りつぶされたパルスは Claude が要求したメモリで、破線の上を飛ぶ中抜きのパルスはフックが勝手に持ってきたものです。ステーションの下で、通常の数字が前者を、`↓` が後者を数えます。
- **コンテキストウィンドウ。** 中心の輪がセッションの進行とともに埋まり、名前の上に割合が表示されます。70% で琥珀色、90% で赤になります。
- **モデルの変更。** 中心とモデルのステーションが数秒間輪を描き、フィードに `opus 5.5 → fable 5.2` のような行が加わります。同じフォルダーの直前のセッションと異なるモデルでセッションが始まった場合も同様です。
- **サブエージェント。** まだ作業中のものは、エージェントのステーションの周りを小さな点で周回し、その呼び出しはそこから始まります。
- **回答。** 回答の準備ができると、中心から一本の太い輪が出ます。

マップの下には、現在実行中の内容を示す行と、直近 16 行（`logRows` を `fill` にするとデスクトップのペインの空きだけ）が並びます。`●` は実行中、`·` は完了、`✕` は失敗またはブロック、`◆` はモデルの変更です。同じステーションで連続して終わった呼び出しは 1 行にまとめられ、名前にあるもののほかに 2 件を表す `+2` が付きます。まだ実行中の呼び出しが後続の行に押し出されることはありません。終了するまで最後の行に残り、一覧とマップが同じ内容を示します。そのような行は一覧の半分以下に抑えられ、それを超えて実行中がある場合は、残りを `+22` のように表示します。

各行は 1 行です。語句はペインの端で切り詰められ、時刻は右端の列に表示されます。メッセージの到着のように時間がかからないものにはダッシュが付き、回答の行にはターン全体の長さが表示されます。ラベルが長い行では時刻の前に `▸` が付き、押すと行全体を表示し、もう一度押すと閉じます。同時に開けるのは 1 行だけです。ターミナルでは、現在の行の右端にコンテキストの割合とモデルも表示されます。描画がないためです。

### 各呼び出しがコンテキストに追加するもの

輪はコンテキストウィンドウの使用率を示します。何がそれを埋めたかは示しません。`contextCost` が有効な場合、呼び出しの行には回答とともにコンテキストがどれだけ増えたかが時刻の後に表示されます。`85 ms +42k` のような形です。マップでは、各ステーションの件数の行にセッション全体の合計が加わります。`9 · 180k` のような形です。数値は隣にあるもの、つまり行では時刻、マップでは件数と同じ色になるため、明るいテーマでも暗いテーマでも読めます。

これは推定値です。Claude Code は、直近の回答にどれだけのトークンを使ったかを mod に伝えます。mod はモデルステップごとのコンテキストの増加量を見て、そのステップに対応する回答を持つ呼び出しに割り当てます。この増加には、モデル自身の発言、フックが追加したもの、ターンの始めであればあなたのメッセージも含まれます。

- **1 ステップ遅れ。** 呼び出しの数値は、その呼び出しが終わった時点ではなく、次のステップの回答が出た時点で表示されます。ターンの最後のステップで行われた呼び出し、中断されたターンの前の呼び出し、圧縮前の呼び出しには数値が付きません。コンテキストを小さくする圧縮は、どこにも数値を出しません。
- **共有。** 同じステップの呼び出しが 2 つまたは 3 つなら、増加量を均等に分け、数値に `~` を付けます。`~+14k` のような形です。同じステップにそれより多い呼び出しがある場合、大きな読み取りと短いコマンドに同じ数値を与えてしまうため、各行には数値を付けません。すべてが同じステーションなら、そのステーションの合計に全額が入ります。まとめられた行は各呼び出しの数値を合計し、一部に数値がない場合は `~` を付けます。
- **メインループのみ。** サブエージェントは独自のコンテキストを埋めますが、Claude Code はそれを報告しません。その呼び出しには数値が付きません。その回答による増加は、開始したメインループの呼び出しに表示されます。

合計は、マップのすべての描画に表示されます。デスクトップアプリ、VS Code、ターミナルの画像は同じ描画で、点字のマップではステーションの名前の色で、件数の後に `Files 9 +180k` のようにプラスを付けて書かれます。行だけを表示するターミナルでは、同じ書き方で件数の行に表示されます。

点字のマップは、すべてのステーションの合計を描くか、まったく描きません。最も幅の広い合計をすべての名前に並べられるだけの余裕がグリッドになく、ペインが狭い場合や名前が長く件数が大きい場合は、合計をすべて省略し、名前はすべて完全に残し、行には数値が残ります。英語の名前と 10 未満の件数なら 50 列から収まります。すべてのステーションの件数が大きい場合は最大 68 列必要です。

## ターミナルでの表示

ターミナルでは行だけが表示されます。`terminalView` を `picture` にすると、画像を表示できるターミナル（kitty や Ghostty など、iTerm2 では 3.7.8 以降）で、行の上にマップの画像が表示され、デスクトップアプリと同じように動きます。Claude Code はフルスクリーンで描画する必要があります。ペインが会話の横ではなく下にある場合、Claude Code はメイン画面に描画しているため、行だけが残ります。`/tui fullscreen` を入力するか、`CLAUDE_CODE_NO_FLICKER=1 claude` で起動してください。tmux 内では `allow-passthrough on` と `focus-events on` を設定します。他のターミナルでは従来どおり行だけが表示され、幅 24 列未満のペインも同様です。

iTerm2 では画像に 3.7.8 以降が必要です。それより前のバージョンは、送られた画像をタブが閉じるまで保持し続けます。iTerm2 3.7.7 では、動くマップ 1 フレームに約 2 MB、5 分で 17 GB になりました（#81）。そのため画像はオフになり、行の上にその旨を示す行が出ます。iTerm2 を更新するか、`terminalView` を `braille` に設定してください。mod は `TERM_PROGRAM` で iTerm2 を判定し、ssh や tmux 内では `LC_TERMINAL` も使います。バージョンは `TERM_PROGRAM_VERSION` または `LC_TERMINAL_VERSION` から取得し、示されていない場合は画像をオフのままにします。

mod は画像を自分で描きます。描画はデスクトップアプリと同じ `drawMap` の出力を使い、X.Org の misc-fixed ビットマップフォントの文字を使用します。このフォントはパブリックドメインです。出典は [FONTS.md](FONTS.md) を参照してください。マップ上の何かが動いている間は毎秒最大 5 フレーム描画します。画像内の中心が呼吸するのは何かが実行されているときだけで、マップが最後に変わってから 10 分間は滑らかに、その後は 5 秒ごとに 1 フレームになります。軌跡が薄くなれば、静止時には画像も止まります。

`theme` が `auto` の場合、画像はターミナルの `COLORFGBG` に従って明るい配色か暗い配色になります。これは iTerm2、rxvt、Konsole が設定します。何も示されない場合は暗い配色になるため、値を通知しない明るいターミナルでは `theme` を `light` に設定してください。画像自体には背景がないため、ターミナルの背景が透けます。それがペインの灰色とわずかに異なる場合、マップの周りに薄い枠が残ります。`paneBackground` を `transparent` にすると灰色が消え、マップと行の両方でターミナルが背後に表示されます（ターミナル自体が透過している場合も含みます）。ターミナルの色を `#rrggbb` で指定すると、その色でペインを描画します。`colors` に `background=#rrggbb` を指定すると、画像に独自の背景を与えられます。

また、ターミナルはセルの高さを教えてくれません。`cellShape` がそれを指定します。セルが幅の何倍の高さかを表し、既定値は 2.4 です。これは iTerm2 が Monaco 12 を描画する比率で、kitty の Menlo では約 2 です。画像の下に空白の帯ができるなら値を上げ、右に帯ができるなら下げてください。

### 点字ドットのマップ

`terminalView` を `braille` にすると、マップは行の上にテキストのセルとして表示されます。スポーク、ステーション、中心は点字ドットで、名前は文字で描かれます。画像は不要で、点字を収めたフォントがあればよいため、Windows Terminal や多くの Linux ターミナル（`picture` が何も表示しない環境）に表示できます。これは代替手段ではありません。画像を表示できないターミナルでは、あなたが自分で `braille` を選ぶまで行だけが表示されます。

![The braille map in Windows Terminal](docs/map-braille.png)

同じ盤面で、同じ読み方ができます。1 セルが持てるものは次のとおりです。

- **ステーション。** 空の輪はまだ使われていません。点が入った輪は使われたことがあり、塗りつぶされた輪は現在作業中で鼓動しています。終わったばかりのステーションは数秒間明るいままです。赤はエラーまたは拒否で、名前の後の `!1` は次のあなたのメッセージまでの数です。`x3` はその場所で同時に実行中の呼び出し数です。`contextCost` が有効で、グリッドに全ステーション分の余裕がある場合、ステーションの合計が件数の後に `Files 9 +180k` のように表示されます。
- **スポーク。** スポークは最初の呼び出しでステーションの色を取り、使われると 2 本目の線が加わります。呼び出しが始まると光り、パルスが飛んでいき、終わると戻ります。フックが勝手に持ってきたものは、そのステーションから飛び込んできます。
- **中心。** 外周はコンテキストウィンドウで、上から時計回りに埋まります。70% で琥珀色、90% で赤になり、名前の上に割合、下にモデルが表示されます。モデル名は変更後数秒間明るくなります。回答の準備ができると中心から一本の輪が出ます。
- **サブエージェント。** まだ作業中のものは、エージェントのステーションの周りを点で周回します。

描かれないものは次のとおりです。1 セルが持てる色は 1 つで、点が持てる詳細も 1 つだけだからです。

- ステーション間の経路と、薄くなる軌跡
- 作業中のステーションの周りの時計針
- ステーション内のアイコン、破線の輪郭、中心の呼吸
- パルスが着地する輪と、モデルが変わるときの輪
- 並ぶパルス。同時に始まった呼び出しは 1 つとして飛び、`x3` が数を示します
- フックが勝手に持ってきたものを数えるメモリの 2 つ目の数字 `↓`。1 つの数字が両方を数えます
- サブエージェントの呼び出しがエージェントのステーションから出る様子。すべての呼び出しが中心から飛びます
- 光のフェード。ステーションは明るくなり、その後そうでなくなります

色はマップ自身の色で、デスクトップアプリと同じです。`theme` と `colors` は有効で、`auto` の場合は画像と同じく `COLORFGBG` によって明るい配色か暗い配色になります。何も示されない場合は暗い配色なので、値を通知しない明るいターミナルでは `theme` を `light` に設定してください。ここでの `background` の意味も画像の場合と同じです。

- `solid`（既定）：セルはパレットの背景色の上に置かれ、文字はその文字色になります。どんなペインでもマップが読めます。ペイン自身の地の色は Claude Code のテーマから取得しますが、マップからは照会できません。それとターミナルが異なる場合（暗いテーマの下で明るいターミナルなど）、画像と同じく、暗いペインの中に明るいマップになります。
- `transparent`：セルには地の色がなく、文字はターミナル自身の色になります。ターミナルと Claude Code のテーマが一致する場所で選んでください。そうするとマップは枠なしでペインに収まります。両者が異なると文字がほとんど読めなくなります。`paneBackground` も `transparent` なら、マップとペインの両方でターミナルが背後に表示されます。

`layout` で輪を回せます。`motion` を `reduced` にすると、何も飛ばず、鼓動せず、周回もしません。呼び出しはステーションとスポークを光らせ、サブエージェントはその隣に留まります。

画像と同じく、マップが表示されるのはペインが会話の横にある場合だけです。Claude Code の既定のレンダラーではペインは会話の下にあり、マップには高さが足りないため行だけが残ります。`/tui fullscreen` を入力するか、`CLAUDE_CODE_NO_FLICKER=1 claude` で起動してください。マップには本体の幅が 50 列、高さが 25 行以上必要で、最大 76 列 × 21 行を使います。それより小さいペインでは行だけが残ります。再描画は見た目が変わるときだけです。パルスが飛んだりサブエージェントが周回しているときは毎秒約 8 回、作業中のステーションが鼓動するたびに描画し、静止時にはまったく描きません。マップが最後に変わってから 10 分経つと、まだ実行中のものは 5 秒ごとに 1 フレームになります。

## VS Code での表示

VS Code 拡張機能ではペインが低く、ペインいっぱいの幅で描いたマップは収まりません。そこでのみ、現在の行の末尾に 3 つのボタンが並びます。**Zoom out** と **Zoom in** はマップを 160〜400 ピクセルの 6 段階、またはペインいっぱいの幅で描画します。**Hide map** はペインをその 1 行に折りたたみ、**Show map** はマップを戻します。選択は次のセッションにも保持されます。

## オプション

インストール時に画面で選択できます。後からは、ターミナルで `/config` または `claude plugin configure` を使い、セッションを再起動してください。以下では 4 つのグループに分けます。すべてに既定値があり、何も設定しなくてもマップは動作します。

### 外観

各オプションの値の画像は [オプションの見た目](docs/options.md) を参照してください。

| オプション | 既定値 | 意味 |
| --- | --- | --- |
| `language` | `en` | `en`、`ru`、`es`、`fr`、`de`、`it`、`pt` のいずれか |
| `coreName` | `CLAUDE` | 中央の円に表示する文字。最大 10 文字 |
| `theme` | `auto` | マップの配色。`dark`、`light`、または表面の明暗に合わせる `auto` |
| `background` | `solid` | マップ自身の背景。背後のペインを透かす `transparent` も指定できます。ラベルの縁は背景色を保つため、異なる色の表面では淡いハローとして見えます |
| `paneBackground` | `theme` | ペイン自身の塗り色。Claude Code 自身の `theme`、壁紙やぼかしを含むターミナルを透かす `transparent`、または不透明なターミナルに合わせる `#rrggbb` 形式の色。対応しない表面は独自の色を保ちます。[ターミナルでの表示](#in-a-terminal) を参照 |
| `colors` | なし | 独自の色。それぞれ `name=#rrggbb` 形式。[独自の色](#colours-of-your-own) を参照 |
| `layout` | `you-top` | マップ上であなたがいる位置。`you-top`、または輪を半周回してあなたを下に、ネットワークとブラウザを上に置く `you-bottom` |
| `motion` | `full` | `full`、または何も飛んだり広がったり回ったりしない `reduced`。呼び出しはステーションを光らせスポークを閃光させ、経路に区間が加わります。それらは薄くなるだけです。実行中のステーションの時計針は、時計のようにゆっくり動き続けます |
| `textSize` | `footnote` | マップの下の行のサイズ。`caption`、`footnote`、`body`。ターミナルはサイズが 1 つだけで、この値を無視します |
| `openAtStart` | `true` | セッション開始時にペインを自動で開くか。`false` なら `/lot-map` を入力するまで閉じたままですが、最初の呼び出しからマップは保持されるため、開いたときには完全な内容になります |
| `logRows` | `16` | マップの下の一覧が表示する行数。`16`、またはマップの下のペインの空きだけ表示する `fill`（最小 16 行）。収まらない古い行は、実行中の呼び出しの上で下端から切り詰められます。デスクトップアプリのドッキングペインのみ。ターミナル、エディター、モバイルアプリは 16 行のままです |

### 表示内容

| オプション | 既定値 | 意味 |
| --- | --- | --- |
| `hookReasons` | `false` | フックの拒否理由の先頭 1 行を最大 72 文字表示します。オフなら、どのツールが止められたかだけを表示します |
| `guardedHooks` | `true` | トランスクリプトに `lot-map: its classic.PreToolUse hook was skipped` のような通知が出る Team または Enterprise のログインではオフにしてください。組織のガードが 5 つのイベントから mod を遠ざけるため、オフにすると mod はそれらにフックを追加しません。マップはフックのステーション、フックが追加した記録、入力したスラッシュコマンドの行、圧縮の印を失います。フックに拒否された呼び出しは、ブロックではなく失敗として `✕` が付きます |
| `subagentNames` | `false` | サブエージェントのモデルステップに、開始時の短い説明（最大 40 文字）でどのサブエージェントかを表示します。オフなら、サブエージェントであることだけを表示します |
| `contextCost` | `false` | 各行に、その呼び出しの回答でコンテキストがどれだけ増えたかを表示し、マップに各ステーションの合計を加えます。推定値で 1 ステップ遅れて表示されます。[各呼び出しがコンテキストに追加するもの](#what-each-call-adds-to-the-context) を参照 |
| `contextWindow` | `model` | 輪と割合がコンテキストを何に対して測るか。`model` はステータス行と同じくモデルのウィンドウ全体、`compaction` は `autoCompactWindow` などで設定される自動圧縮のウィンドウで、モデルのものより小さくなります。設定がない場合や自動圧縮がオフの場合、`compaction` は `model` と同じ内容を表示します。ウィンドウはセッションの最初のモデルステップ、圧縮後、モデル変更時に読み取られます。`guardedHooks` がオフの場合は圧縮後には読み取りません |

### メモリとサーバー

| オプション | 既定値 | 意味 |
| --- | --- | --- |
| `memoryServers` | `memory` | ツールがメモリを光らせる MCP サーバー |
| `memoryCommands` | なし | メモリを光らせるシェルコマンドやスクリプト。コマンド名そのもの、または名前に `-`、`_`、`.` が続く場合に一致します。そのため `recall` は `recall-sync.py` も指します |
| `memorySubcommands` | なし | メモリコマンドの後に続く語のうち、マップが表示してよいもの。`add` や `search` など。指定しない場合、コマンドは名前だけで表示されます |
| `memoryPaths` | なし | ファイルをメモリとみなすパスの一部 |
| `memoryLabels` | なし | メモリツールの短い名前。それぞれ `tool=name` 形式 |
| `serverStations` | なし | MCP サーバーのツールを任意のステーションに置きます。それぞれ `server=station` 形式で、`files`、`shell`、`web`、`browser`、`agents`、`skills`、`you` が使えます。行には引き続き `server: tool` と表示されます。設定した内容は、mod が既知のサーバーに対して持つ独自の経路より優先されます。メモリは `memoryServers` を保持し、両方に含まれるサーバーではそれが優先されます。未知のステーションは無視されます |
| `hookRecords` | `false` | あなたのフックが `[#123]` のような番号付きメモリ記録を追加する場合にオンにしてください。メモリに番号だけが表示されます。任意のフックの本文にあるそのような番号も、メモリフックでなくても数えられます |

### ターミナル専用

| オプション | 既定値 | 意味 |
| --- | --- | --- |
| `terminalView` | `text` | ターミナルでのマップの表示形式。`text` は行だけ、`picture` は画像を表示できるターミナル（iTerm2 は 3.7.8 以降）で行の上にマップの画像、`braille` は点字フォントのあるターミナルで行の上に点字のマップ。[ターミナルでの表示](#in-a-terminal) を参照 |
| `cellShape` | `2.4` | ターミナルの画像用。セルが幅の何倍の高さかを 1.2 から 4 の範囲で指定し、画像を枠いっぱいにします。[ターミナルでの表示](#in-a-terminal) を参照 |

例えば、ロシア語のラベルと独自のメモリサーバーは次のように設定します。

```bash
echo '{"language":"ru","memoryServers":"my-memory"}' | claude plugin configure lot-map@lot-map --values-stdin
```

画像を表示しないターミナルでマップ自体を表示するには：

```bash
echo '{"terminalView":"braille"}' | claude plugin configure lot-map@lot-map --values-stdin
```

Team または Enterprise のログインでスキップされたフックの通知を止めるには：

```bash
echo '{"guardedHooks":"false"}' | claude plugin configure lot-map@lot-map --values-stdin
```

すべての値は文字列として書き込みます。`"false"` や `"2.4"` も同様です。リストはカンマ区切りで書きます。

## 独自の色

`colors` はマップの色を 1 つずつ置き換えます。1 つ、いくつか、または 13 すべてを設定できます。省略した色はそのままです。

```bash
echo '{"theme":"dark","colors":"accent=#7fb4ff,active=#b8d6ff,text=#e6edf7"}' | claude plugin configure lot-map@lot-map --values-stdin
```

| 名前 | 着色するもの |
| --- | --- |
| `background` | マップの地の色と、ラベルの縁 |
| `node` | ステーションと中心の内側 |
| `line`, `spoke` | 破線の輪郭と、待機中のスポーク |
| `text`, `label`, `faint` | 中心の名前と光っているラベル、その他のラベル、件数 |
| `accent`, `active` | 主色と、作業中のステーション |
| `error` | エラーと拒否 |
| `memory`, `memoryActive` | メモリのステーションとそのスポーク |
| `route` | ステーション間の経路 |

<img src="docs/map-colors.png" width="640" alt="The map in two palettes of one's own: a cool blue one and a green one">

- 受け付けるのは `#rgb` と `#rrggbb` だけです。それ以外や未知の名前は未設定として扱われます。
- `theme` を `auto` のままにすると、独自の色は明るい表面でも有効で、残りはこれまでどおり塗り直されます。パレット全体を独自にする場合は `theme` を `dark` か `light` に設定してください。
- `background` を `transparent` にした場合も、ここではペインの色を `background` に指定してください。ラベルの縁にその色が使われ、ハローが消えます。

## 表示するものと保持するもの

この mod はネットワークリクエストを行わず、ファイルを読みまず、プロセスを実行せず、モデルを呼び出さず、会話に何も追加しません。行はセッションの間だけ存在します。同じ内容を 1 ページにまとめたものが [プライバシー](PRIVACY.md) です。

ツール呼び出しを追跡する他の mod と同様、すべての呼び出しの入力全体（コマンド行やファイルに書き込まれるテキストを含む）が渡されます。mod が取り出すのはそこから名前だけで、それを行うコードは `hooks/classify.ts` の `classify` です。このリポジトリから追加されたマーケットプレースは `main` ブランチを追うため、更新ではその時点の内容が入ります。問題であれば、更新前に差分を読んでください。

既定では、Claude Code に 1 つのことだけを尋ねます。各モデルステップの後でコンテキストウィンドウがどれだけ埋まっているかです。`contextCost` が有効な場合、同じ回答からトークン数も保持して各行とステーションに数値を表示しますが、それ以上に読み取るものはありません。`contextWindow` を `compaction` にすると、セッションの最初のモデルステップと、圧縮またはモデル変更の後に、コンテキストの内訳も尋ね、回答から自動圧縮ウィンドウのサイズだけを取り出します。セッションの間で保持するのは 1 つだけ、フォルダーごとに最後に使ったモデル名です。変更を表示するためです。それぞれ、フォルダーのフルパスをキーにして Claude Code のプラグイン用ストアに保存されます。

フックの動作は次のとおりです。この mod はセッションの開始、プロンプト、ターン、モデルステップ、ツール呼び出し、スキル、圧縮、`subagentNames` が有効な場合はサブエージェントの開始に加え、設定フックの 3 つのイベントを監視します。`PreToolUse` では、フックが呼び出しを拒否したか、権限を求めたか、時間を取ったかを確認します。`UserPromptSubmit` と `SessionStart` では、フックが追加したコンテキストを確認します。各フックはイベントをそのまま渡し、返ってきたものもそのまま返します。入力も、結果も、コンテキストも、権限の決定も変更せず、独自の決定も行いません。唯一のコマンド `/lot-map` はペインを開きます。

ラベルには内容ではなく名前だけが入ります。

- ファイル：パスの末尾 2 要素。
- Web アドレス：ホスト名のみ。ログイン、パスワード、パス、クエリは含みません。2 通りに読めるアドレスはスキームだけを表示します。
- シェルコマンドやモニター：Claude が付けた短い説明、またはコマンド名。コマンド行そのものは表示しません。説明はモデル自身の言葉で、そのまま表示されます。
- 検索：`Grep` と `Glob` ではツール名、Web 検索では `web search`、ツール検索では `loading tools` をマップの言語で表示します。パターンやクエリは表示しません。
- メモリ呼び出し：ツール名と記録番号または短い識別子。本文やクエリは表示しません。
- メモリコマンド：名前と、`memorySubcommands` に挙げた語だけが続く場合のその語。
- サブエージェント：開始時に渡された短い説明。`subagentNames` が有効な場合は、そのサブエージェントのモデルステップにも先頭 40 文字を表示します。
- バックグラウンドタスクの報告：タスクが終了したことと失敗したかどうかだけ。要約や出力は表示しません。
- フックの拒否：停止されたツールの名前。先頭 1 行は `hookReasons` が有効な場合だけ表示されます。拒否にフックが見つけた内容が引用されることがあるためです。

すべてのラベルは描画前に制御文字が取り除かれます。

マップ上の不具合がツール呼び出しやモデルターンに波及することはありません。

## 開発

```bash
claude plugin test .
claude plugin validate .
```

文言は `hooks/text.ts` にあります。言語を 1 つ増やすには、そこに表を 1 つ追加し、`.claude-plugin/plugin.json` の `language` に値を 1 つ追加します。

ターミナルの画像は 3 つのファイルで作られます。`hooks/scene.ts` が `drawMap` の描画を読み、`hooks/raster.ts` がそれを描画し、`hooks/png.ts` がピクセルをターミナル用に詰めます。テストはすべての種類の描画を描き、描画側が知らないものがあれば失敗します。そのため、より多くの SVG 機能を必要とする描画の変更はまずここで現れます。別のテスト「the terminal picture's font has every letter the map writes, in every language」は、新しい言語に必要な文字を `hooks/font.ts` に追加すべきことを示します。そのファイルの再作成方法は [FONTS.md](FONTS.md) を参照してください。

点字のマップは `hooks/braille.ts` が描きます。同じ盤面の別の描画で、ステーションは `STATIONS` から、タイミングは `hooks/draw.ts` から取得します。`hooks/braille.test.tsx` のテストは、両方のレイアウトですべてのステーションを描くことを確認し、`hooks/lot-map.test.tsx` のテストはすべての言語の名前を確認します。マップに何か新しいものを追加したら、そこにも描画するか、[ターミナルでの表示](#the-map-in-braille-dots) の点字が省くものの一覧に加えてください。`hooks/braille.test.tsx` の `INVENTORY` には最初の描画が示すものが 1 行ずつあり、テストが両方の描画をそれに照らし、`scripts/check-surface.mjs` がその一覧を同じ行に照らします。

変更を送る前に [CONTRIBUTING.md](CONTRIBUTING.md) を読んでください。この mod が守ることと、各項目の背後にあるチェックは [PRINCIPLES.md](PRINCIPLES.md) にあります。
